# spec-0106: A region holds a whole site — a place of the site plan is built the whole-site way, with its own ground and its own light, a map of many such places is joined by seams, and `areas[]` is removed

- **Status**: Proposed
- **Ground**: written against engine `5961145d83362036b714a13ae251faf3ba2c760f` (`main`), read only — `Placement`, `Extent` (`crates/dsl/src/placement.rs`); `SitePlanContent`, `PlanBox`, `Base`, `Ceiling`, `Fill` (`crates/dsl/src/siteplan/mod.rs`); `Site::bottom`, `Site::column_bottom`, `Site::shell` (`crates/dsl/src/siteplan/claim.rs`); `DW0826` (`siteplan/region.rs`); `Frame`, `Detail`, `DetailPlanContent` (`crates/dsl/src/detailplan.rs`); `DW0843`–`DW0845`, `DW0987` and `place` (`crates/delvec/src/compiler/detail.rs`); the relight pass's reading of a bound place (`crates/delvec/src/compiler/light.rs`); `surround_rect` and `DW0855` (`crates/delvec/src/compiler/plan/surround.rs`); the crossing sweep's second shape (`crates/delvec/src/compiler/blockout.rs`); `well_formed` in `crates/delvec/src/grammar/contract.rs`; `Area`, `Pieces` (`crates/dsl/src/world.rs`); the `area.<a>.name` key (`crates/dsl/src/l10n.rs`); `DW0869`/`DW0870` (`crates/dsl/src/layout.rs`); the test `crates/delvec/tests/one_place_site.rs`; `docs/reference/compiler.md` (*The map pipeline — `site-plan`*, *`detail-plan`*, *The horizon's surround*, *The blockout*, *A piece's blocks arrive as one template or as a tile set*); `docs/reference/grammar.md` §2d; `docs/research/how-a-large-level-is-actually-built.md` §1.3, §1.4, §1.6; ADR-0004, ADR-0006, ADR-0032; spec-0049, spec-0050, spec-0052, spec-0098 §2, §2c, §5, §14; spec-0103 and `references/partitioning.md` on the branch that carries it. The campaign records: the content tag `release/vesperhold/v1.1.0` (`campaigns/vesperhold/`, `prefabs/vesperhold.json`, `design/programs/vesperhold.json` through LFS), built with the engine release it pins (`delvec--v1.8.1`, `dsl 0.35.1`); the content branch `campaign/stranding` at `0d1f897363fff1b76ca483519cf2dde1c66f09cd` (`campaigns/the-stranding/`, `docs/stranding-creation-problems.md`).
- **What it is for**: a map that grows past one author's attention is divided into **regions**, each built the way Vesperhold was built — one grammar program drawing a whole site, ground, water, walls, roofs and all, with its places inside it — and the regions are joined by seams. One worker owns one region; the largest region is a Vesperhold-scale build, which is the one point this engine has verified; every region can be built to completion. Below that size a map is one region, because the record (§1) shows that a whole built as one program joins its places more organically and carries more detail than the same places built as separate pieces inside separate boxes. `areas[]` stops being a way to place a map; what it could express moves onto the place. A prefab stays usable — as a whole place, or placed inside a place's program by name — and nothing draws one from a pool: at this scale how pieces are assembled is designed (§3.3, §3.8, ADR-0035).
- **The words**: the direction this spec executes calls the unit a **region**. The engine's object for it already exists and is **a place** — a layout-graph node with its box in the site plan — and this spec adds no second noun: the engine gains no `regions[]`, and the site plan's `region` field keeps meaning what it means today, the whole map's bounds (§3.6 names the rename that frees the word, as an implementation choice). The creator's guide says once that a region is a place authored as one whole, as spec-0103's page says once that a district is what its direction called an area.
- **Research**: §1 is the record of two campaigns read against each other, each finding marked **measured** (a number read from a document or a build) or **inferred** (a reading of the derivation's rules against the record). Each rule below is marked **cited** (a source in §1, a reading of the tree, a constitution rule) or **authored** (this spec chooses). The guide (§8) marks every recommendation the same way and names the signal that would show it wrong.
- **Numbers**: spec-0106. `dsl_version` **0.44.0** for the implementation (free on every remote ref at the ground revision; the highest held is 0.41.0). Three DW codes: **`DW1021`** (§4), **`DW1022`** (a seated prefab's declared opening answered by nothing, §3.9) and **`DW1023`** (an extraction met a declared object its derivation cannot place, §3.9); nothing else this spec adds is a refusal an existing code or a named expansion gate does not already name. **ADR-0035** (§10) supersedes ADR-0004 and amends ADR-0032 §2.
- **Non-goals**: a second map route (ADR-0032 stands: one site plan; this spec changes what a place may hold, not how a map is placed); a size refusal (CLAUDE.md: a check confirms intent and never restricts — the ceiling is the guide's, stated beside a measured census, §8); a scoped station namespace (`anchor/<place>/<name>`; §3.7 keeps the flat namespace and names the falsifier); a packet or dispatch procedure (spec-0103's, §5); a drawing medium for a region (ADR-0032 §5 stands; a region's medium is the grammar program, as Vesperhold's is); authoring the migration of any campaign other than the one §6 names, or authoring the nine-region level's content.

## 1. The record: a whole built as one program, against the same kind of whole built as places

Two campaigns reached a designed exterior at a scale of twenty or more places. **Vesperhold** (`release/vesperhold/v1.1.0`) is one piece: a 172 × 104 × 292 grammar program expanded at seed 1 into 84 structure tiles, bound to one `areas[]` entry under a `valley` horizon. **The Stranding** (`campaign/stranding` @ `0d1f8973`) is a site plan: 55 places, each a box with its own program and piece, joined by 64 seams over an `open` heightmap fill. The direction this spec executes judged the first to join its places more organically and carry more detail than the second. This section says where the derivation decides what a whole-site author designs, with the evidence, so that §3 keeps the whole-site way inside a region and does not carry the losses to region scale.

### 1.2 Where the site-plan route loses joins and detail

Each finding names what the derivation decides that a whole-site author designs, whether it comes from the **surface** (the ownership model a site plan states) or from the **step order** (the whole is frozen, then each part is detailed inside it), and what it rests on.

1. **A place is a cuboid, and its outside is a one-cell ring.** A box is play space; a wall stands in the gap between two boxes; a building with an irregular footprint is two boxes and a seam. The Stranding's 55 buildings and open places are 55 cuboids whose walls are one cell thick where they meet (**cited**: compiler.md *the model*; `GENERATION.md` *Placement*: "ring cells where two places touch outside a seam carry a post, so no place leaks into another"). Vesperhold's curtain walls, towers and shelves are whatever the program draws. **Surface.** The loss is not a defect of the model — spec-0098 built it so that a whole can be walked before a part exists — but a place whose piece is a whole site has no inner cuboids and no inner rings, so inside a region the loss does not arise.
2. **A join is a declared cell on a declared face.** A seam is one opening standard or one contact span at an offset the plan states, cut by the derivation; the piece answers it exactly (`DW0844`, cell for cell) or is refused. A whole-site program places a doorway where the room wants it and changes its mind for free. **Surface** — and the right one between two authors, because the seam is the only sentence both sides read. Inside a region there are no seams, so the loss is confined to region boundaries, which §8 puts where the design already has an edge.
3. **A piece never sees its neighbour.** The handout gives a place the seam's `form` sentence, the fixed ring and its own frame, and nothing of the neighbour's facade, roofline or material (**cited**: spec-0098 §4; ADR-0032's revisit trigger "a scene that must know its neighbour"). Two Stranding houses that share a street were drawn from two sentences. **Surface**, inherent to parallel authorship. Inside a region the author sees everything; §5 names what a region's worker is handed about the neighbour at the boundary.
4. **The ground between places is nobody's design.** 85% of The Stranding's columns are the `fill`'s heightmap, dressed afterwards by world-edits; the author's note on it is the falsifier spec-0098 §13 already recorded ("the terrain wants dressing"). Vesperhold's valley floor, moat and crag are drawn by the same program that draws the castle, at the same density. **Surface.** A region owns its ground (§3.1), so the commons between regions is only the seam's width.
5. **The whole is frozen before any part is drawn, and a part cannot move it.** A detail finding that needs a plan edit re-opens every place (`stranding-creation-problems.md` row 2: half a day; row 16: two places' stations deadlock per-place detail). Vesperhold's author re-ran the whole generator on every change. **Step order** (spec-0049's principle, kept on purpose: a plan is cheap to move only while nothing is built on it). Inside a region the author's loop is the whole-site loop again; between regions the step order stands and is the price of parallel work.
6. **Fifty-five pieces from one author is a generator, not fifty-five designs.** The Stranding's author wrote a geometry model that emitted every place's program rather than designing each against its handout (**cited**: spec-0103 §1, and `GENERATION.md` *The map*: "one geometry model … writes … every place's program"). Vesperhold's author wrote one generator for one castle. **Neither surface nor step order**: the number of parts one attention held. It is the reason a region is sized to one author's whole, and the reason the ceiling of one region is the largest whole one author has finished.

**What is not lost, and is kept.** Every proof over bytes (`DW0836`–`DW0838`, `DW0986`, `DW0990`, reach, light, danger) is indifferent to who wrote the blocks (**cited**: ADR-0032 §3); the handout and the frame are what make a boundary designable by two authors at all; a stand-in never ships. This spec changes nothing about them.

## 3. The surface

### 3.1 A place owns its ground: `base: {"owned": n}` **[authored, on §1.2 finding 4 and spec-0098 §2]**

`boxes[].base` gains a third variant beside `"ground"` and `{"aloft": n}`:

| `base` | the claim's bottom | the ring's ground | the terrain |
|---|---|---|---|
| `"ground"` (default) | per column, the lower of the floor course and the terrain's walk plane, stopping one course over a place stacked under it | fixed by the whole at and under the ground height (`DW0990` first shape) | continued to the plot's edge |
| `{"aloft": n}` | `floor − 1 − n` everywhere | none fixed | may not reach the claim (`DW0990` third shape) |
| **`{"owned": n}`** | **`floor − 1 − n` everywhere** | **none fixed: the ring is the place's, ground and all** | **stops at the claim: inside the footprint and ring the terrain is the piece's; under the claim's bottom the fill writes its ground as everywhere else** |

An owned-ground place is a whole site standing on the whole's subsoil: the piece draws its valley floor, its moat, its crag and its bedrock course, and the fill's `below` block meets it from underneath. The one rule it owes is that the whole's ground reaches it: in every column of its footprint and ring the terrain's surface stands at or above `floor − 2 − n`, so the piece's bottom course rests on ground and never on the air an `open` fill leaves above its surface (`DW1021`, §4). A `solid` fill has nothing to refuse. Terrain standing higher than the bottom inside the footprint is the piece's to replace and is counted, not refused: the allocation prints the columns clipped.

Everything else about a box is unchanged: `extent` is the play space, the ring is one cell, the claim is the frame (`DW0843`, exact), the piece voids what it does not own (`DW0987`), two claims sharing a cell go to spec-0098 §2's rules, and a seam on an owned-ground place is cut and answered exactly as on any other. Where two owned-ground places meet along a contact, the shared ring column goes to the `a` of the seam (rule 3c), so the join is drawn by one author over continuous ground.

### 3.2 A place is lit by declaration: `boxes[].lighting`, `boxes[].mitigation` **[authored, on G2 and G3; the object is `AreaLighting`, cited]**

`boxes[]` gains the two optional fields `areas[]` carried, with the same types and the same range rule (`DW0196`). `boxes[].lighting` relights the **bound piece's** reachable walkable cells to `min_light` with `fixture`, exactly as `areas[].lighting` relit a prefab's — the declaration is the author's intent that the whole hang the fixtures, which is the one thing spec-0050 §3 refused to do unasked, and it stays refused unasked: the plan's `lighting` still reaches derived interiors only. A dark bound place with no `boxes[].lighting` is `DW0210` naming the piece, as today. `boxes[].mitigation` emits the night-vision tick over the box's claim as the area's did over its placed bounds. The two fields are named where the capability acts (CLAUDE.md: a capability belongs to the object class it acts on), and `Placement::lighting_field` and `has_area_mitigation` are struck with the enum that carried them.

### 3.3 `areas[]` is removed, assembly is designed and never drawn, and a prefab stays usable **[the ruling; ADR-0035, cited; CLAUDE.md "Nothing owes compatibility"]**

`world.json` loses `areas[]`; with it go `Area`, `Pieces`, `AreaLighting`'s home on an area, `AreaMitigation`'s, `DW0160`, `DW0839` (one authority, now the only one), `Placement` (every campaign's placement is its site plan or nothing; `DW0824`'s "no plan" finding is the one remaining state), `Extent::OnePiece`/`Unstated` (`DW0855` keeps one arm: a terrain-building horizon on a campaign with no site plan), the `AREA_SPACING` stride and the inter-area `transport` teleport, and the `area` field on `quest-plan.quests[]`, `npcs[]`, `world-edits.batches[]` and loot containers (G10). The anchor table is keyed by name.

**The pool and jigsaw assembly is deleted entirely** (ADR-0035 §3): `prefab_pool`, `pieces{min, max}`, the jigsaw solve (`compiler::solver`'s layout solve and `seal_layout`, `compiler::pool`, `DW0498`, `DW0306`'s socket arm), `prefabs/pools.json` and its readers, the jigsaw `Connector` vocabulary as an assembly contract and the socket-carving verb, the L2 massing verbs of `world-edits.json` (`swap-piece`, `insert-piece`, `remove-piece`, `rewire-socket`, `reseed-piece`, `DW0324`'s arm), `delvec prefab seating` and `tools/ci/check-seating-agrees.py` (a step of the `gallery-views` job in `.github/workflows/ci.yml`; the job stays, so no required context moves), and the piece-mating check's `by_socket` arm (`compiler::faces` judges contract faces alone). No seed draws a piece anywhere, on the map or inside a region: where a prefab stands and what it joins is stated by the author (§3.8).

**The stage-7 `fragment` stamp is removed** (ADR-0035 §4): it is the one other channel a prefab had into a place, and it writes over a bound frame's bytes with nothing comparing the two (§1.1, the Stranding's record on the stamp). A prefab inside a region is placed where the region is authored.

A document carrying any removed field is refused by the schema (`DW0100`, naming the field) — no second code, no shim, no flag. A released campaign is built by the engine it pins and is owed nothing. The gallery's primary places `areas[]` today (three areas, one a pool) and becomes a site plan (§9).

### 3.4 A place with no seam owes no way in **[authored, on G4]**

`grammar::contract::well_formed` demands an `exterior` traversal edge on the entry space because a place is entered through a seam. A place the plan allocates **no seam** to — a one-place map, or a region entered only by a `carry` — has no exterior, and its entry is the `spawn` or the carry's mark; its contract declares zero exterior edges and the gate states the zero in its enumeration instead of refusing. The rule is keyed to the place's seam count, read from the plan the way scenery is read from the graph (`admit::scenery::is_scenery`), never to the piece's own word. A piece with a seam is judged as today.

### 3.5 Binding an admitted piece: `delvec detail <campaign> <place> --piece <prefab>` **[authored, on G5]**

One verb details a place (spec-0058); `--piece` is its second door, for a piece already in the library — a whole site expanded by its own generator, as Vesperhold's is. The verb computes the frame, judges the piece against it (`DW0843`, `DW0844`, `DW0987`, `DW0990`, and `DW0845` over the owed names), binds every owed name to the piece anchor of the same local name (`anchor/great-hall` → `great-hall`; `anchor/node-<place>` and `spawn` to the anchor carrying `role: entry`, else refused naming both), writes the `details[]` row, and prints one binding line: owed names bound of owed, piece anchors no station names (counted, legal — the mid-authoring state), stations declared. A name with no same-named anchor is `DW0842` with the piece's nearest names. `--piece` and a program at `programs/<stem>.json` on the same place is a refusal naming both doors.

### 3.6 Names **[authored]**

The site plan's `region` field means the whole map's bounds and this spec does not change it; the implementation may rename it `bounds` in the same change, since the word "region" is what the guide and the direction use for a place built whole and `dsl_version` moves anyway. It is a DSL field rename and merges mechanically; the spec does not depend on it.

### 3.7 Stations stay flat **[authored, with the falsifier]**

A station's name is unique across the campaign's one area (`DW0870`), so nine copies of one region declare nine names for one spot (`anchor/great-hall-2`, …) — the "small edits" of §7. A place-scoped namespace (`anchor/<place>/<name>`) would spare the renaming and is not built: it changes the id grammar every quest verb reads for a case the demo level reproduces with a substitution. The falsifier is the first campaign brief that cannot state its places with suffixed names.

### 3.8 A prefab in a region: two grains of one mechanism **[decided on the research of ADR-0035; the operation is authored]**

The question put to the research — is a prefab a part of a region, placed beside authored work, or a whole region with its openings declared in advance — has one answer with two grains, and the evidence (ADR-0035 *Context*, cited there) supports stating them as one mechanism:

- **A prefab as a whole place** exists today and is kept unchanged: `detail-plan.details[].piece` binds any admitted piece, `DW0843` holds its size to the frame, `DW0844` holds its contract's faces to the plan's seams, `base: {"owned": n}` lets it own its ground (§3.1), and `--piece` writes the row (§3.5). This is a region that is one prefab with its openings declared in advance — Vesperhold is one — and it is the degenerate case of the next grain: a program of one operation.
- **A prefab inside a place's program** is new: the grammar gains one operation, `{"op": "prefab", "piece": "prefab/<id>", "rotation"?}`, that places the admitted piece's blocks at the scope's box, which must equal the piece's size exactly (a part exceeding its box is a refusal, ADR-0032; undersize refuses as oversize does, as `DW0843` has it), imports the piece's anchors under `mark`'s naming (`anchor/<stem>`, `index: auto` for a piece placed more than once), and joins its contract's spaces and edges to the program's contract under the scope's claim name, with its exterior faces becoming edges to the enclosing spaces they meet. The expansion is **one piece** — the region's — so every proof reads one piece, the stamp-over-a-frame defect cannot arise, and the exported prefab's provenance row records every library piece it holds (ADR-0013). **Which piece stands where is a function of the program's documents alone, never of the seed** (ADR-0035 §3): a `prefab` operation reached through a weighted choice among a rule's alternatives is refused by a named expansion gate, `prefab-placed-by-design`, beside `contract-well-formed`; a piece the library does not hold, or a scope box of the wrong size, is refused by the expansion's existing block-existence and shape gates, each naming the piece and the box. The operation takes no `pool`, no weight and no count.

A library piece is a part by every source the research read — a kit piece inside a layout a person authored — and a region of one library piece meets a region's duties only because the plan's gates read the piece and not its provenance (spec-0050). So the test for "is this prefab a whole region" is not a property of the prefab: it is whether its box is the region's and its faces answer the region's seams, which `DW0843` and `DW0844` already decide. **What a prefab IS, on this evidence, is a cuboid of designed work with its openings declared** — the property the second model asked for — and §3.9 derives exactly that from a built campaign: the openings are the plan's seams at the cuboid's boundary, the ground is what the place owned, the names are its stations. Whether such a prefab is then a whole region or a part inside one is decided at seating, by the box it is given, not by the prefab.

### 3.9 A prefab is extracted from a campaign and seated in another **[the direction; the derivation is authored on the tree's own objects]**

A prefab is a reusable piece of designed work. Two properties are required of its format, and every field of it is a procedural derivation handed by the tool (CLAUDE.md): what the tool cannot derive is a finding in the derivation, never a field the author types.

**Extraction.** One command, one derivation, restricted to a **scope**: `delvec prefab extract <campaign> --scope <scope> -o <prefabs-dir>`, where the scope is one of three kinds — **a place or several adjoining places** (`node/<a>[,node/<b>…]`; the cuboid is the union of their frames), **a declared structure by id** (a program `claim` name of a bound place, an assembly, a `forms/` sculpt, a gate anchor's region; the cuboid is the declaration's own box, read from the piece's contract or the campaign's document), or **a cuboid of coordinates** (`--scope x0,y0,z0..x1,y1,z1`). A prefab is never bound to being a whole region: the wanted thing is often one building of a town, one tower of a castle, or the contents of a box an author points at, and the command serves all of them with the same pass. It reads the campaign's documents and the assembled model of its build (so world-edits, the relight pass's fixtures and every stage-7 write inside the scope are in the bytes), and writes `<id>.json` and the `.nbt` tiles. Everything in the document is derived, and the table is the format:

| field | derived from |
|---|---|
| `structure_set` (tiles, size, grid) | the scope's cuboid; cells inside it the scope's places do not own (a place scope) are `structure_void` (`Frame.voids`), as a bound piece already carries them; a coordinate or structure scope carries every cell of its box |
| `openings[]` — each `{name, face, cells, kind, rise, opening, source}` | **at a place boundary**: the plan's seams joining an extracted place to a place outside the cuboid — the cells they allocate (`PlacedSeam`), the edge's class, the derived rise, the standard or declared size, `source: seam`; **at a cut** (a coordinate or structure scope's face through a place): every run of walkable floor or water the nav model finds meeting the cut face becomes a **candidate** opening — its cells, its kind from the walk model (walk, stair, drop, climb, swim), its rise against the piece's walk plane, `source: cut` — and a solid face is a wall; a seam between two extracted places, or a seam the cut passes through, becomes an internal edge of the contract or a candidate opening by the same rule |
| `ground` — `{owned: n}` or the fixed-ring record | the places' `base` and the frame's `fixed` cells |
| `anchors` | every station of the places, bound through the `details[]` rows, with its kind from the piece anchor's shape; the gate regions of `barred` seams inside the cuboid as gate anchors; the entry's `spawn` as the anchor carrying `role: entry` |
| `spatial_contract` | the pieces' contracts joined: their spaces and edges, the internal seams as edges, the `openings[]` as exterior faces |
| `lighting`, `mitigation` | the places' `boxes[].lighting` / `mitigation` (§3.2), plus the measured light record `delvec prefab` already writes |
| `atmosphere` | the places' `boxes[].atmosphere`, one or refused (a cuboid under two skies is two prefabs) |
| `entities[]` | every actor, NPC body, assembly and furniture the campaign places inside the cuboid from world load, with its mark and the document that declared it — recorded, so a seating knows what the bytes do not hold |
| `license.provenance` | the source campaign id and content revision, the places' node ids, each source piece's own provenance row (ADR-0013), the engine revision (`delvec --version`) and the build's `manifest.json` hash |

**What crosses the scope's boundary is derived from the cut, never typed, and what cannot be derived is printed as residue.** A gate whose other side lies outside, a station a quest outside the scope names, a volume, a pulse or an assembly reaching across the boundary, an atmosphere boundary inside the scope: each is **dropped and listed by name** in the extraction's report and in the prefab's `residue[]`, with the object's id, its document and what severed it. What an arbitrary cut leaves unestablished is printed as explicit residue too — `lighting adequacy not established: <n> dark cells within <k> of the cut`, `entry not inside the scope: the entry is the first candidate opening`, `<n> candidate opening(s) await a neighbour` — and every residue row is a **seating-time check** in the new campaign (`DW0210` on the seated place's light, `DW1022` on every opening, `DW0837` on reach from the seated `spawn`), never a field the author types. A whole-region extraction (a place scope whose boundary is all seams and commons) is the case with **zero residue**, and the command prints that zero; a cut costs exactly what it severs, and the command says what that is. A declared object the derivation can neither carry nor drop by a rule above is `DW1023`, naming the object and the row it could not fill, and the remedy is a change to this derivation, stated in those words. The extraction is deterministic (ADR-0006): two extractions of one build are byte-identical.

| scope kind | derives | cannot derive, and says so |
|---|---|---|
| a place, or several | everything in the table; openings from the plan's seams; ground from `base`; the entry from the node's `spawn`; the contract from the pieces' | nothing at a region's own boundary (zero residue); objects reaching outside the set are listed |
| a declared structure by id | the cuboid from the declaration; the declaration's own record (the assembly's parts, the form, the claim's spaces) carried whole; anchors and entities inside | openings — candidates from the cut; the entry; light at the cut; references leaving the box, listed |
| a cuboid of coordinates | the bytes, anchors, entities, fixtures and enclosed spaces inside, the spaces found by the walk model | the same as a structure scope, and no declaration names the thing: the prefab's `license.provenance` says it is a cut and from where |

**Seating.** `delvec prefab seat <campaign> <prefab> --node <node> --at <x>,<z> [--floor <y>]` writes what the prefab determines and nothing the author would otherwise type (a prefab seated inside another place's program is the `prefab` operation of §3.8 instead, with its openings joined to the program's spaces by the program's own edges): the `boxes[]` row (`extent` from the cuboid less its ring, `floor` from the prefab's walk plane at the given `y`, `ceiling`, `base` from `ground`, `lighting`, `mitigation`, `atmosphere`), the node's `stations[]` from `anchors`, the `details[]` row with its `anchors` map, and one `seams[]` stub per declared opening carrying `opening: {"declared": "<name>"}` — a seam form in which `face`, `at` and the size are derived from the prefab and `edge`, `form` and the neighbour are the author's. The author's two creative decisions are the ones the direction names: where the place stands (`--at`, `--floor`), and which declared opening joins which neighbour (the seam's `edge`, naming the layout graph's connection). Every declared opening is answered, at validation, by a seam or by the explicit disposition `"opens": "commons"` on an `open` site; an opening answered by nothing is `DW1022`, naming the opening and both remedies. A seam whose neighbour's floor does not meet the opening's rise is the existing `DW0829`/`DW0830`; a station name the new campaign already holds is the existing `DW0870`, with the remedy a rename in the seating's `stations[]`; a prefab whose `ground` is owned on a `solid` fill is seated without a ring and the fill meets it as §3.1 says. Nothing about a seated prefab is special after seating: it is a `details[]` row like any other, judged by `DW0843`, `DW0844` and every gate that reads a bound piece.

### 3.10 An extracted prefab is stored, and its source is a lock record inside it **[authored, on ADR-0006, ADR-0013 and the rule that a released campaign builds only with the engine it pins]**

Once extraction exists, a campaign that reuses a prefab could either take it from the content library's `prefabs/` as bytes, or name a source — a released campaign tag plus a scope — and extract it when it builds. **Decision: the bytes are stored in the content library, through LFS as every piece is, and the source is a lock record inside the prefab's own document**: `license.provenance.extracted` = `{campaign, tag, scope, engine, manifest, digest}` — the source campaign id, the content tag or commit it was built at, the scope as given, the engine release that built the source and ran the extraction, the source build's `manifest.json` hash, and the sha256 of the extracted tiles and document. The record is derived by `extract` and read by `delvec prefab audit`, which, where the source is reachable, re-extracts and compares digests and otherwise states that it could not; it is a cache key and a provenance row (ADR-0013), never an input to a build.

**Why not extract at build time.** A released campaign is never edited and is built only by the engine revision it pins, so an on-demand extraction cannot rebuild the source with the consumer's engine. It would read the released artifacts — the delve image's saved world and the release's `manifest.json` from the registry, and the tag's documents from the content repository — and the consuming campaign's build would then depend on a network fetch, on the registry's and the release's retention, and on a reader of the saved world's region files the engine does not have; the determinism promise (ADR-0006: same documents and seed, byte-identical output) would rest on a fetched artifact's digest rather than on bytes the build holds, and a creator's offline build (CLAUDE.md: everything runs on the creator's own machine) would be impossible on the first run and only cached after it. The cache that makes it tolerable — a lock record of tag, scope and digest, and a local copy of the bytes — is what storing the bytes already is, with the record carried in the piece instead of beside it. Measured cost the alternative would add: rebuilding a source instead of fetching it costs The Stranding's 14 to 20 minutes per consumer build on this project's development host; fetching costs the first run's download of a saved world (The Stranding's: 61 452 KiB in 9 region files) per source. Stored, the cost is paid once by whoever extracts, in LFS bytes the content repository already carries for every piece.

**What stays stored regardless.** The content library is where every campaign's own pieces already live — `delvec detail` writes them there, and The Stranding's 55 pieces are its — and the engine repository's `prefabs/*-generator` workspaces and `prefabs/invariants` are tooling, not pieces; neither moves with this decision. `prefabs/pools.json` goes with the pools (§3.3) and nothing else in `prefabs/` is read by a pool.

**How the reference-works page points at a source.** The skill's `references/reference-works.md` already names each work by a content tag or commit, read by URL and never copied; a reusable piece lifted from a work is named there by its library id and the `extract` invocation that produced it (the tag and the scope), so a reader walks from the page to the piece and from the piece's lock record back to the page's source, and nothing is stated twice.

**The alternative declined, with its cost.** Name the source and extract at build time: it keeps the content library free of reused bytes and makes staleness impossible, at the cost above — a network and registry dependency inside a build, a world-file reader, a first run that cannot be offline, and a determinism promise anchored outside the build's inputs. The one case it serves better — a source re-released with a fix every consumer should pick up — is answered by re-running `extract` and committing the new bytes, which the lock record makes a one-line comparison.

**The three measurements** (criteria 14, 15 and 16). Vesperhold's castle, extracted from the one-region campaign of §6 and seated again as the one region of a fresh campaign, builds the same world with zero residue: this is criterion 1's instrument run a second time, with the extracted prefab in place of the hand-admitted one, and its fixtures already in the bytes, so the relight line counts zero new fixtures. The Stranding's creature — the body's inside and outside places, extracted as one place scope from `campaign/stranding`'s build — seated in a fresh one-region campaign on an `open` fill, every opening disposed to the commons, builds and walks: its route proof reaches every station from the seated `spawn`. One tower of Vesperhold (or one building of The Stranding's town), extracted as a cuboid of coordinates cut through its region, prints a residue that is exactly what the cut severs — the candidate openings where its stair and its door meet the cut, the gate or station the cut parts from its quest, the dark cells at the cut — and seats and builds in a fresh campaign with each residue row answered at seating.

## 4. `DW1021` — an owned-ground place stands over air (validation tier) **[authored]**

Refused per place, naming the place, the first column (`x, z`) where the `open` fill's terrain surface stands below `floor − 2 − n`, by how many courses, and how many columns of its footprint and ring do so. The remedy is a terrain or `base` edit, named in the message: raise the terrain under the plot, deepen `owned`, or make the fill `solid`. Zero columns is printed in the plan's binding line with the count of owned-ground places examined. A `solid` fill raises nothing. The code is new because no existing rule reads the terrain against a declared bottom from below: `DW0990`'s third shape reads it from above, for a place that hangs.

## 5. Relation to the districts of spec-0103

spec-0103 (on its own branch, implemented there, not on `main`) gives a worker a **district**: a declared set of layout-graph nodes, with a packet derived per district, fragments of the stage documents under `districts/<x>/`, a write set the commit hook refuses outside of, and a ledger that routes a whole-campaign red to its district. Its places are the Stranding's: small boxes, one piece each, one author per set of them.

This spec and spec-0103 are **one mechanism at two grains, and the direction fixes the grain**: a worker owns one region, and a region is one place. Under this spec a district is therefore always a set of one node, and a partition into singletons is a census derivable from the plan, never hand-written (CLAUDE.md). What spec-0103 built that this spec needs is everything but the partition: the packet (what a worker is handed about its region and every boundary seam, including the connection contract of spec-0103 §6.3), the fragments (so nine workers do not write one `quests.json`), the write set and its hook, `validate --district`, and the routing ledger. So:

- **Decision, ruled**: spec-0103's unit is re-keyed from a declared `districts[]` set to **the place**: `districts/<x>/` becomes `regions/<node>/`, `--district <x>` becomes `--region <node>`, `DW1003` (the partition is ill-formed) has nothing left to refuse and is struck, `DW1007`'s size advice is replaced by §8's ceiling stated against the census, and the packet's `places[]` is one allocation. Nothing else in spec-0103 §5–§9 changes. The revised text is `docs/specs/spec-0103-a-delve-is-authored-in-parallel-by-region.md` on this spec's branch, carrying the loosening in those words (a many-place district is no longer expressible); the branch that implements the first text reworks its thirty files to it before it merges.
- **The alternative, declined**: keep `districts[]` as an optional grouping above places, so one worker may take several small regions. It keeps a second noun and a second authority for "what a worker owns", which the direction forbids, for a case §8 answers differently: several small places that want one author are one region.
- The partitioning guide spec-0103 §4 names (`references/partitioning.md`) is the one page; §8 is the text added to it, and its first recommendation is this spec's. Its two worked examples stand as records of how two maps divided and are re-read as regions when the branches meet. The districts demo level, The Toll Fair, is re-scoped in the revised spec-0103 §11.2 to three regions each built whole; its row in `docs/demo-levels.md` exists only on the implementing branch and is re-scoped there.

## 6. The Vesperhold migration, and its instrument **[criterion 1]**

Vesperhold v1.1.0 becomes a site plan of one owned-ground place whose piece is `prefab/vesperhold`, its program carried over unchanged except for what §2 names. The migration is a content change on a content branch, built by the implementing engine; this section states what moves and how equality is measured.

**What moves.** `world.json`: `areas[]` gone; `lighting {torch, 3}` moves to the box. `geometry-brief.json`: at least one fact (the castle's footprint, 172 and 292, from `DESIGN.md`'s heights and the generator's layout). `layout-graph.json`: one node, `entry` = `goal` = the node, `critical_path` of one step, every objective's beat on the node, and one station per name the quests and NPCs reference, each with its kind from the piece's anchor shape (`point` for a `pos`, `gate` for a `region`); the two `anchor/unlock-…` names are renamed out of the reserved namespace in the quests and the piece alike. `site-plan.json`: bounds `[0, 56, 0]` + `[172, 104, 292]` (the piece's box at the position the `areas[]` seating gave it: origin `y` = the valley walk reference 64 minus `walk_y` 8); one box pinned at `[1, 1]` with `extent [170, 290]`, `floor {"y": 64}`, `ceiling {"open": 96}`, `base {"owned": 7}`, `lighting {torch, 3}`; `fill` `open`, flat on a datum at 56 (its surface at 55, the course under the piece), bedrock as `surface` and `below`; one identity holding the bounds to the brief's fact; no seam, no volume, no view (each zero stated). `detail-plan.json`: one row, written by `delvec detail --piece`. `prefabs/vesperhold.json`: a `spatial_contract` with one `open` space over the whole and zero exterior edges (§3.4), the two anchors renamed; the `.nbt` tiles untouched. `quest-plan.json`, `npcs.json`, `world-edits.json`: the `area` fields removed (§3.3). The numbers above are the author's derivation and `delvec allocation` is the authority: the frame it prints must be `172 × 104 × 292` at `[0, 56, 0]` with zero fixed cells and zero voids, or the plan is wrong, not the piece.

**The instrument.** Byte equality is measured at **one engine revision that builds both forms**: the implementation branch at the commit before `areas[]` is removed, which carries §3.1, §3.2, §3.4 and §3.5. Both forms of the campaign are built from one content tree — the piece amended as above, the quests with the two names renamed, documents stamped to the implementing `dsl_version` by `delvec fmt` — once with `areas[]` and once as the plan, with the same `--prefabs` and the same seed, twice each (ADR-0006). Every file of the two output trees — `datapack/`, `resourcepack.zip` unpacked, `creator-datapack/`, `packtest-datapack/`, `server/` — is hashed and listed; the expected difference is exactly the resource pack's two lang files, each by the one `delve.vesperhold.area.castle.name` key (G9), and nothing else; the `validation/` artifacts are compared separately and their differences listed, since a plan build writes records an `areas[]` build does not (`blockout.json`). The compiler's assembled model (`compiler::assembled::placed_blocks`) is compared cell by cell for the two forms and the differing-cell count is printed: the expected number is zero. The binding lines of the plan build are read: surround authority `site-plan region`, the same template and biome-band counts as the `areas[]` build, relight fixtures placed inside the piece with the same count, `0 place(s) massed`, `DW0838` with zero unclaimed standable cells. The hashes, the counts and the revision are written in the commit body of the commit that removes `areas[]`; the comparison script is committed as `tools/ci/compare-build-trees.py` (two output trees in, a per-file hash table and the list of differing files out, exit 1 on any difference not named on its allowlist argument) so the claim is re-runnable. Any remainder beyond the lang key is a named debt in this spec's *Recorded debts*, never a pass.

## 8. The creator's guide: dividing a map into regions **[lands on `references/partitioning.md`; part of this spec]**

Added to the one page as its first section, before *What a district is*. Every recommendation is **authored** unless marked **cited**; each states its reasoning and the signal that would show it wrong. The page is revised as campaigns are made.

**A region is a place authored as one whole.** Inside it the author works the whole-site way: one program draws the ground, the walls, the roofs, the water and the places within, as Vesperhold's does, and the engine checks it. The direction this engine follows calls that unit a region; the engine's object is the layout-graph node with its box, and spec-0103's district is a set of one.

**The verified ceiling of one region** (**cited**: the content tag `release/vesperhold/v1.1.0`, `prefabs/vesperhold.json`, `campaigns/vesperhold/DESIGN.md`, `GENERATION.md`): a 172 × 104 × 292 piece — 50 224 columns, 71 103 standable cells, 43 303 reachable on foot — holding 42 designed places, 144 named spots (137 points, 7 gate regions), 3 shortcut doors, 13 quests with 37 objectives, 16 waves, about an hour of play, drawn by one 52.9 MB program from one generator, built and played to completion. A region larger or denser than this is **unverified**: nothing says it fails, and nothing says it builds. The census the engine prints for every place — the frame's extent and cells (`delvec allocation`), its templates, its share of the world-build chain (`DW0984`) — is what a new region is read against.

**Recommendation 1 — build as one region until a stated signal says the whole is too large for one author's attention; then divide** (**authored**). The reasoning: the record (spec-0106 §1) shows a whole built as one program joins its places and dresses its ground better than the same places built as separate pieces, because inside one program nothing is a declared cell and the author sees everything; the losses of dividing are confined to the boundaries, so the fewer boundaries the better, down to none. The **signal**, authored, not measured: divide when the brief exceeds Vesperhold on any one count — more than about 40 designed places, a footprint over about 50 000 columns (about 170 × 290), more than about 150 named spots, or more than one hour of play inside one continuity — or when the brief itself names two wholes (two castles, a town and its harbour, an island and its lighthouse) that the fiction treats as separate. The starting threshold is Vesperhold because it is the one verified point and because the only comparable record of one author holding more parts (The Stranding at 55 places across 55 pieces) ended in generation rather than design. **What would show it wrong**: a region at or under the threshold that an author cannot finish (the threshold is too high — lower it to the size that was finished), or a two-region map at the threshold whose seam the owner's walk cannot find (the threshold is too low — raise it to the size that still reads whole). Record either on this page with the campaign that showed it.

**Recommendation 2 — divide where the design already has an edge** (**cited**: Lynch's edge, "the boundaries between two phases, linear breaks in continuity", *The Image of the City*, already on this page; spec-0103's two worked examples place every boundary at water, a wall with a door, a stair, a drop or a carry). A seam is a crossing cut at a declared cell on a declared face, drawn by two authors from one sentence; it costs least where the player already expects a break — a river, a curtain wall and its gate, a cliff and its stair, a change of ground — and most through continuous fabric, a street or a hall, where a one-cell wall and a declared doorway are exactly the losses spec-0106 §1.2 names. **Signal**: a render of two regions at their seam that reads as a cut.

**Recommendation 3 — the division depends on what is being made** (**authored**, reasoned from the ceiling and from spec-0103 §4's tests):

| the whole | divide it | the reasoning | what it trades |
|---|---|---|---|
| a small town, a camp, one castle and its approach | **do not divide**: one region | under the ceiling; every join is drawn, the ground is one design | all of the detail; one author's whole effort; consistency for free |
| a city, a castle complex of several wholes, a town and its harbour | **one region per castle, never per house**: a cluster of like buildings sharing one continuity is one region, and each building is a place inside its program (**cited**: WesterosCraft fixes per-region style guides and lays out plots inside them, research §1.6; Skyrim's kits fix a kit's standards before eight designers build with it, §1.3) | a house is below any author's ceiling and a boundary between two houses runs through continuous fabric (recommendation 2); a castle is the largest verified whole | per-region detail at Vesperhold's density; one author per region; consistency held by the whole's reference sheet, the palette (`detail-plan.palette`) and every seam's `form`, and weakest at seams through fabric |
| a reconstruction of a continent, a coast, a valley system | **one region per landscape unit** — a valley, a bay, a ridge — bounded by water, ridgeline or cliff, each holding its few buildings | the player reads the landscape, not the buildings; building density per region is low, so a region's budget goes to ground; the natural edges are Lynch's | less detail per building than a castle region; many regions, so many workers; consistency held by a shared heightmap at the boundary and the terrain's own continuity |

**Where established practice informs this and where it stops** (**cited**): engines keep the whole as one persistent artifact and hand it authorial chunks — Unreal's World Partition stores one level in grid cells and places Level Instances by the world (research §1.4); the macro layout is drawn first and renegotiated while soft (The Witcher 3's pins on a map; Breath of the Wild's Kyoto overlay, §1.4); build teams fix per-region style and lay out plots before building (§1.6); kits fix standards before designers build (§1.3). None of these is a rule for sizing an authorial unit to one author's attention — streaming cells are sized to memory and draw distance, not to attention, and the only attested per-area ownership (Dark Souls, §1.4) held coherence in one director's head, which this pipeline does not have. So the sizing rule above is authored, the division lines are cited, and few test cases exist: how stable an agent's authoring is at a given size is what the nine-region level and the next campaigns measure.

## 10. The decision record: ADR-0035

ADR-0032 §2 reads: "`areas[]` remains the engine's assembly surface for library pools and is not a map route the skill presents." This spec removes `areas[]` and with it the pool and jigsaw assembly ADR-0004 decided. An Accepted decision is never edited; **ADR-0035** (`docs/adr/0035-a-prefab-is-placed-by-a-plan-never-drawn-by-a-solver.md`, Proposed) supersedes ADR-0004 in full and amends ADR-0032 §2: a map is placed by its site plan and nothing else; a prefab is a part a plan or a program places, in the two grains of §3.8; assembly is designed, never drawn, and no seed draws a piece anywhere. It carries the research the two-model question was decided on. Criterion 10 holds the implementation to landing this spec and the record's acceptance together, and ADR-0004's status line moves to *Superseded by ADR-0035* at that acceptance.
