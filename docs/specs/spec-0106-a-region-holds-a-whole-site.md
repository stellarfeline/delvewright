# spec-0106: A region holds a whole site — a place of the site plan is built the whole-site way, with its own ground and its own light, a map of many such places is joined by seams, and `areas[]` is removed

- **Ground**: written against engine `5961145d83362036b714a13ae251faf3ba2c760f` (`main`), read only — `Placement`, `Extent` (`crates/dsl/src/placement.rs`); `SitePlanContent`, `PlanBox`, `Base`, `Ceiling`, `Fill` (`crates/dsl/src/siteplan/mod.rs`); `Site::bottom`, `Site::column_bottom`, `Site::shell` (`crates/dsl/src/siteplan/claim.rs`); `DW0826` (`siteplan/region.rs`); `Frame`, `Detail`, `DetailPlanContent` (`crates/dsl/src/detailplan.rs`); `DW0843`–`DW0845`, `DW0987` and `place` (`crates/delvec/src/compiler/detail.rs`); the relight pass's reading of a bound place (`crates/delvec/src/compiler/light.rs`); `surround_rect` and `DW0855` (`crates/delvec/src/compiler/plan/surround.rs`); the crossing sweep's second shape (`crates/delvec/src/compiler/blockout.rs`); `well_formed` in `crates/delvec/src/grammar/contract.rs`; `Area`, `Pieces` (`crates/dsl/src/world.rs`); the `area.<a>.name` key (`crates/dsl/src/l10n.rs`); `DW0869`/`DW0870` (`crates/dsl/src/layout.rs`); the test `crates/delvec/tests/one_place_site.rs`; `docs/reference/compiler.md` (*The map pipeline — `site-plan`*, *`detail-plan`*, *The horizon's surround*, *The blockout*, *A piece's blocks arrive as one template or as a tile set*); `docs/reference/grammar.md` §2d; `docs/research/how-a-large-level-is-actually-built.md` §1.3, §1.4, §1.6; ADR-0004, ADR-0006, ADR-0032; spec-0049, spec-0050, spec-0052, spec-0098 §2, §2c, §5, §14; spec-0103 and `references/partitioning.md` on the branch that carries it. The campaign records: the content tag `release/vesperhold/v1.1.0` (`campaigns/vesperhold/`, `prefabs/vesperhold.json`, `design/programs/vesperhold.json` through LFS), built with the engine release it pins (`delvec--v1.8.1`, `dsl 0.35.1`); the content branch `campaign/stranding` at `0d1f897363fff1b76ca483519cf2dde1c66f09cd` (`campaigns/the-stranding/`, `docs/stranding-creation-problems.md`).
- **What it is for**: a map that grows past one author's attention is divided into **regions**, each built the way Vesperhold was built — one grammar program drawing a whole site, ground, water, walls, roofs and all, with its places inside it — and the regions are joined by seams. One worker owns one region; the largest region is a Vesperhold-scale build, which is the one point this engine has verified; every region can be built to completion. Below that size a map is one region, because the record (§1) shows that a whole built as one program joins its places more organically and carries more detail than the same places built as separate pieces inside separate boxes. `areas[]` stops being a way to place a map; what it could express moves onto the place.
- **The words**: the direction this spec executes calls the unit a **region**. The engine's object for it already exists and is **a place** — a layout-graph node with its box in the site plan — and this spec adds no second noun: the engine gains no `regions[]`, and the site plan's `region` field keeps meaning what it means today, the whole map's bounds (§3.6 names the rename that frees the word, as an implementation choice). The creator's guide says once that a region is a place authored as one whole, as spec-0103's page says once that a district is what its direction called an area.
- **Research**: §1 is the record of two campaigns read against each other, each finding marked **measured** (a number read from a document or a build) or **inferred** (a reading of the derivation's rules against the record). Each rule below is marked **cited** (a source in §1, a reading of the tree, a constitution rule) or **authored** (this spec chooses). The guide (§8) marks every recommendation the same way and names the signal that would show it wrong.
- **Numbers**: spec-0106. `dsl_version` **0.44.0** for the implementation (free on every remote ref at the ground revision; the highest held is 0.41.0). One DW code, **`DW1021`** (§4); `DW1022` and `DW1023` were handed and are not consumed — nothing this spec adds is a refusal an existing code does not already name. **No new ADR number is handed; §10 names the ADR consequence the planner allocates.**
- **Non-goals**: a second map route (ADR-0032 stands: one site plan; this spec changes what a place may hold, not how a map is placed); a size refusal (CLAUDE.md: a check confirms intent and never restricts — the ceiling is the guide's, stated beside a measured census, §8); a scoped station namespace (`anchor/<place>/<name>`; §3.7 keeps the flat namespace and names the falsifier); a packet or dispatch procedure (spec-0103's, §5); a drawing medium for a region (ADR-0032 §5 stands; a region's medium is the grammar program, as Vesperhold's is); authoring the migration of any campaign other than the one §6 names, or authoring the nine-region level's content.

## 1. The record: a whole built as one program, against the same kind of whole built as places

Two campaigns reached a designed exterior at a scale of twenty or more places. **Vesperhold** (`release/vesperhold/v1.1.0`) is one piece: a 172 × 104 × 292 grammar program expanded at seed 1 into 84 structure tiles, bound to one `areas[]` entry under a `valley` horizon. **The Stranding** (`campaign/stranding` @ `0d1f8973`) is a site plan: 55 places, each a box with its own program and piece, joined by 64 seams over an `open` heightmap fill. The direction this spec executes judged the first to join its places more organically and carry more detail than the second. This section says where the derivation decides what a whole-site author designs, with the evidence, so that §3 keeps the whole-site way inside a region and does not carry the losses to region scale.

### 1.2 Where the site-plan route loses joins and detail

Each finding names what the derivation decides that a whole-site author designs, whether it comes from the **surface** (the ownership model a site plan states) or from the **step order** (the whole is frozen, then each part is detailed inside it), and what it rests on.

1. **A place is a cuboid, and its outside is a one-cell ring.** A box is play space; a wall stands in the gap between two boxes; a building with an irregular footprint is two boxes and a seam. The Stranding's 55 buildings and open places are 55 cuboids whose walls are one cell thick where they meet (**cited**: compiler.md *the model*; `GENERATION.md` *Placement*: "ring cells where two places touch outside a seam carry a post, so no place leaks into another"). Vesperhold's curtain walls, towers and shelves are whatever the program draws. **Surface.** The loss is not a defect of the model — spec-0098 built it so that a whole can be walked before a part exists — but a place whose piece is a whole site has no inner cuboids and no inner rings, so inside a region the loss does not arise.
2. **A join is a declared cell on a declared face.** A seam is one opening standard or one contact span at an offset the plan states, cut by the derivation; the piece answers it exactly (`DW0844`, cell for cell) or is refused. A whole-site program places a doorway where the room wants it and changes its mind for free. **Surface** — and the right one between two authors, because the seam is the only sentence both sides read. Inside a region there are no seams, so the loss is confined to region boundaries, which §8 puts where the design already has an edge.
3. **A piece never sees its neighbour.** The handout gives a place the seam's `form` sentence, the fixed ring and its own frame, and nothing of the neighbour's facade, roofline or material (**cited**: spec-0098 §4; ADR-0032's revisit trigger "a scene that must know its neighbour"). Two Stranding houses that share a street were drawn from two sentences. **Surface**, inherent to parallel authorship. Inside a region the author sees everything; §5 names what a region's worker is handed about the neighbour at the boundary.
4. **The ground between places is nobody's design.** 85% of The Stranding's columns are the `fill`'s heightmap, dressed afterwards by world-edits; the author's note on it is the falsifier spec-0098 §13 already recorded ("the terrain wants dressing"). Vesperhold's valley floor, moat and crag are drawn by the same program that draws the castle, at the same density. **Surface.** A region owns its ground (§3.1), so the commons between regions is only the seam's width.
5. **The whole is frozen before any part is drawn, and a part cannot move it.** A detail finding that needs a plan edit re-opens every place (`stranding-creation-problems.md` row 2: half a day; row 16: two places' stations deadlock per-place detail). Vesperhold's author re-ran the whole generator on every change. **Step order** (spec-0049's principle, kept on purpose: a plan is cheap to move only while nothing is built on it). Inside a region the author's loop is the whole-site loop again; between regions the step order stands and is the price of parallel work.
6. **Fifty-five pieces from one author is a generator, not fifty-five designs.** The Stranding's author wrote a geometry model that emitted every place's program rather than designing each against its handout (**cited**: spec-0103 §1, and `GENERATION.md` *The map*: "one geometry model … writes … every place's program"). Vesperhold's author wrote one generator for one castle. **Neither surface nor step order**: the number of parts one attention held. It is the reason a region is sized to one author's whole, and the reason the ceiling of one region is the largest whole one author has finished.

**What is not lost, and is kept.** Every proof over bytes (`DW0836`–`DW0838`, `DW0986`, `DW0990`, reach, light, danger) is indifferent to who wrote the blocks (**cited**: ADR-0032 §3); the handout and the frame are what make a boundary designable by two authors at all; a stand-in never ships. This spec changes nothing about them.

## 3. The surface

### 3.1 A place owns its ground: `base: {"owned": n}` **[authored, on §1.2 finding 4 and spec-0098 §2]**

`boxes[].base` gains a third variant beside `"ground"` and `{"aloft": n}`:

| `base` | the claim's bottom | the ring's ground | the terrain |
|---|---|---|---|
| `"ground"` (default) | per column, the lower of the floor course and the terrain's walk plane, stopping one course over a place stacked under it | fixed by the whole at and under the ground height (`DW0990` first shape) | continued to the plot's edge |
| `{"aloft": n}` | `floor − 1 − n` everywhere | none fixed | may not reach the claim (`DW0990` third shape) |
| **`{"owned": n}`** | **`floor − 1 − n` everywhere** | **none fixed: the ring is the place's, ground and all** | **stops at the claim: inside the footprint and ring the terrain is the piece's; under the claim's bottom the fill writes its ground as everywhere else** |

An owned-ground place is a whole site standing on the whole's subsoil: the piece draws its valley floor, its moat, its crag and its bedrock course, and the fill's `below` block meets it from underneath. The one rule it owes is that the whole's ground reaches it: in every column of its footprint and ring the terrain's surface stands at or above `floor − 2 − n`, so the piece's bottom course rests on ground and never on the air an `open` fill leaves above its surface (`DW1021`, §4). A `solid` fill has nothing to refuse. Terrain standing higher than the bottom inside the footprint is the piece's to replace and is counted, not refused: the allocation prints the columns clipped.

Everything else about a box is unchanged: `extent` is the play space, the ring is one cell, the claim is the frame (`DW0843`, exact), the piece voids what it does not own (`DW0987`), two claims sharing a cell go to spec-0098 §2's rules, and a seam on an owned-ground place is cut and answered exactly as on any other. Where two owned-ground places meet along a contact, the shared ring column goes to the `a` of the seam (rule 3c), so the join is drawn by one author over continuous ground.

### 3.2 A place is lit by declaration: `boxes[].lighting`, `boxes[].mitigation` **[authored, on G2 and G3; the object is `AreaLighting`, cited]**

`boxes[]` gains the two optional fields `areas[]` carried, with the same types and the same range rule (`DW0196`). `boxes[].lighting` relights the **bound piece's** reachable walkable cells to `min_light` with `fixture`, exactly as `areas[].lighting` relit a prefab's — the declaration is the author's intent that the whole hang the fixtures, which is the one thing spec-0050 §3 refused to do unasked, and it stays refused unasked: the plan's `lighting` still reaches derived interiors only. A dark bound place with no `boxes[].lighting` is `DW0210` naming the piece, as today. `boxes[].mitigation` emits the night-vision tick over the box's claim as the area's did over its placed bounds. The two fields are named where the capability acts (CLAUDE.md: a capability belongs to the object class it acts on), and `Placement::lighting_field` and `has_area_mitigation` are struck with the enum that carried them.

### 3.3 `areas[]` is removed, and the `area` fields with it **[authored, on the direction; CLAUDE.md "Nothing owes compatibility"]**

`world.json` loses `areas[]`; `Area`, `Pieces`, `AreaLighting`'s home on an area, `AreaMitigation`'s, `prefab_pool` and the jigsaw solve (`compiler::solver`'s pool arm, `compiler::pool`, `DW0498`), `DW0160`, `DW0839` (one authority, now the only one), `Placement` (every campaign's placement is its site plan or nothing; `DW0824`'s "no plan" finding is the one remaining state), `Extent::OnePiece`/`Unstated` (`DW0855` keeps one arm: a terrain-building horizon on a campaign with no site plan), the `AREA_SPACING` stride and the inter-area `transport` teleport, the L2 massing verbs of `world-edits.json` (`swap-piece`, `insert-piece`, `remove-piece`, `rewire-socket`, `reseed-piece`, `DW0324`'s arm), `delvec prefab seating` and `tools/ci/check-seating-agrees.py` (a step of the `gallery-views` job in `.github/workflows/ci.yml`; the job stays, so no required context moves), and the `area` field on `quest-plan.quests[]`, `npcs[]`, `world-edits.batches[]` and loot containers (G10). The anchor table is keyed by name. A document carrying any removed field is refused by the schema (`DW0100`, naming the field) — no second code, no shim, no flag.

A released campaign is built by the engine it pins and is owed nothing. The gallery's primary places `areas[]` today (three areas, one a pool) and becomes a site plan (§9).

### 3.4 A place with no seam owes no way in **[authored, on G4]**

`grammar::contract::well_formed` demands an `exterior` traversal edge on the entry space because a place is entered through a seam. A place the plan allocates **no seam** to — a one-place map, or a region entered only by a `carry` — has no exterior, and its entry is the `spawn` or the carry's mark; its contract declares zero exterior edges and the gate states the zero in its enumeration instead of refusing. The rule is keyed to the place's seam count, read from the plan the way scenery is read from the graph (`admit::scenery::is_scenery`), never to the piece's own word. A piece with a seam is judged as today.

### 3.5 Binding an admitted piece: `delvec detail <campaign> <place> --piece <prefab>` **[authored, on G5]**

One verb details a place (spec-0058); `--piece` is its second door, for a piece already in the library — a whole site expanded by its own generator, as Vesperhold's is. The verb computes the frame, judges the piece against it (`DW0843`, `DW0844`, `DW0987`, `DW0990`, and `DW0845` over the owed names), binds every owed name to the piece anchor of the same local name (`anchor/great-hall` → `great-hall`; `anchor/node-<place>` and `spawn` to the anchor carrying `role: entry`, else refused naming both), writes the `details[]` row, and prints one binding line: owed names bound of owed, piece anchors no station names (counted, legal — the mid-authoring state), stations declared. A name with no same-named anchor is `DW0842` with the piece's nearest names. `--piece` and a program at `programs/<stem>.json` on the same place is a refusal naming both doors.

### 3.6 Names **[authored]**

The site plan's `region` field means the whole map's bounds and this spec does not change it; the implementation may rename it `bounds` in the same change, since the word "region" is what the guide and the direction use for a place built whole and `dsl_version` moves anyway. It is a DSL field rename and merges mechanically; the spec does not depend on it.

### 3.7 Stations stay flat **[authored, with the falsifier]**

A station's name is unique across the campaign's one area (`DW0870`), so nine copies of one region declare nine names for one spot (`anchor/great-hall-2`, …) — the "small edits" of §7. A place-scoped namespace (`anchor/<place>/<name>`) would spare the renaming and is not built: it changes the id grammar every quest verb reads for a case the demo level reproduces with a substitution. The falsifier is the first campaign brief that cannot state its places with suffixed names.

## 4. `DW1021` — an owned-ground place stands over air (validation tier) **[authored]**

Refused per place, naming the place, the first column (`x, z`) where the `open` fill's terrain surface stands below `floor − 2 − n`, by how many courses, and how many columns of its footprint and ring do so. The remedy is a terrain or `base` edit, named in the message: raise the terrain under the plot, deepen `owned`, or make the fill `solid`. Zero columns is printed in the plan's binding line with the count of owned-ground places examined. A `solid` fill raises nothing. The code is new because no existing rule reads the terrain against a declared bottom from below: `DW0990`'s third shape reads it from above, for a place that hangs.

## 5. Relation to the districts of spec-0103

spec-0103 (on its own branch, implemented there, not on `main`) gives a worker a **district**: a declared set of layout-graph nodes, with a packet derived per district, fragments of the stage documents under `districts/<x>/`, a write set the commit hook refuses outside of, and a ledger that routes a whole-campaign red to its district. Its places are the Stranding's: small boxes, one piece each, one author per set of them.

This spec and spec-0103 are **one mechanism at two grains, and the direction fixes the grain**: a worker owns one region, and a region is one place. Under this spec a district is therefore always a set of one node, and a partition into singletons is a census derivable from the plan, never hand-written (CLAUDE.md). What spec-0103 built that this spec needs is everything but the partition: the packet (what a worker is handed about its region and every boundary seam, including the connection contract of spec-0103 §6.3), the fragments (so nine workers do not write one `quests.json`), the write set and its hook, `validate --district`, and the routing ledger. So:

- **Decision**: spec-0103's unit is re-keyed from a declared `districts[]` set to **the place**: `districts/<x>/` becomes `regions/<node>/`, `--district <x>` becomes `--region <node>`, `DW1003` (the partition is ill-formed) has nothing left to refuse and is struck, `DW1007`'s size advice is replaced by §8's ceiling stated against the census, and the packet's `places[]` is one allocation. Nothing else in spec-0103 §5–§9 changes. The cost is a rename across the branch's thirty files before it merges, and spec-0103's text revised to say so in the words of a loosening where it is one (a partition of many places into one district is no longer expressible).
- **The alternative, declined**: keep `districts[]` as an optional grouping above places, so one worker may take several small regions. It keeps a second noun and a second authority for "what a worker owns", which the direction forbids, for a case §8 answers differently: several small places that want one author are one region.
- The partitioning guide spec-0103 §4 names (`references/partitioning.md`) is the one page; §8 is the text added to it, and its first recommendation is this spec's. Its two worked examples stand as records of how two maps divided into districts and are re-read as regions when the branches meet.

## 8. The creator's guide: dividing a map into regions **[lands on `references/partitioning.md`; part of this spec]**

Added to the one page as its first section, before *What a district is*. Every recommendation is **authored** unless marked **cited**; each states its reasoning and the signal that would show it wrong. The page is revised as campaigns are made.

**A region is a place authored as one whole.** Inside it the author works the whole-site way: one program draws the ground, the walls, the roofs, the water and the places within, as Vesperhold's does, and the engine checks it. The direction this engine follows calls that unit a region; the engine's object is the layout-graph node with its box, and spec-0103's district is a set of one.

**The verified ceiling of one region** (**cited**: the content tag `release/vesperhold/v1.1.0`, `prefabs/vesperhold.json`, `campaigns/vesperhold/DESIGN.md`, `GENERATION.md`): a 172 × 104 × 292 piece — 50 224 columns, 71 103 standable cells, 43 303 reachable on foot — holding 42 designed places, 144 named spots (137 points, 7 gate regions), 3 shortcut doors, 13 quests with 37 objectives, 16 waves, about an hour of play, drawn by one 52.9 MB program from one generator, built and played to completion. A region larger or denser than this is **unverified**: nothing says it fails, and nothing says it builds. The census the engine prints for every place — the frame's extent and cells (`delvec allocation`), its templates, its share of the world-build chain (`DW0984`) — is what a new region is read against.

**Recommendation 1 — build as one region until a stated signal says the whole is too large for one author's attention; then divide** (**authored**). The reasoning: the record (spec-0106 §1) shows a whole built as one program joins its places and dresses its ground better than the same places built as separate pieces, because inside one program nothing is a declared cell and the author sees everything; the losses of dividing are confined to the boundaries, so the fewer boundaries the better, down to none. The **signal**, authored, not measured: divide when the brief exceeds Vesperhold on any one count — more than about 40 designed places, a footprint over about 50 000 columns (about 170 × 290), more than about 150 named spots, or more than one hour of play inside one continuity — or when the brief itself names two wholes (two castles, a town and its harbour, an island and its lighthouse) that the fiction treats as separate. The starting threshold is Vesperhold because it is the one verified point and because the only comparable record of one author holding more parts (The Stranding at 55 places across 55 pieces) ended in generation rather than design. **What would show it wrong**: a region at or under the threshold that an author cannot finish (the threshold is too high — lower it to the size that was finished), or a two-region map at the threshold whose seam the owner's walk cannot find (the threshold is too low — raise it to the size that still reads whole). Record either on this page with the campaign that showed it.

**Recommendation 2 — divide where the design already has an edge** (**cited**: Lynch's edge, "the boundaries between two phases, linear breaks in continuity", *The Image of the City*, already on this page; spec-0103's two worked examples place every boundary at water, a wall with a door, a stair, a drop or a carry). A seam is a crossing cut at a declared cell on a declared face, drawn by two authors from one sentence; it costs least where the player already expects a break — a river, a curtain wall and its gate, a cliff and its stair, a change of ground — and most through continuous fabric, a street or a hall, where a one-cell wall and a declared doorway are exactly the losses spec-0106 §1.2 names. **Signal**: a render of two regions at their seam that reads as a cut.

**Recommendation 3 — the division depends on what is being made** (**authored**, reasoned from the ceiling and from spec-0103 §4's tests):

| the whole | divide it | the reasoning | what it trades |
|---|---|---|---|
| a small town, a camp, one castle and its approach | **do not divide**: one region | under the ceiling; every join is drawn, the ground is one design | all of the detail; one author's whole effort; consistency for free |
| a city, a castle complex of several wholes, a town and its harbour | **one region per castle, never per house**: a cluster of like buildings sharing one continuity is one region, and each building is a place inside its program (**cited**: WesterosCraft fixes per-region style guides and lays out plots inside them, research §1.6; Skyrim's kits fix a kit's standards before eight designers build with it, §1.3) | a house is below any author's ceiling and a boundary between two houses runs through continuous fabric (recommendation 2); a castle is the largest verified whole | per-region detail at Vesperhold's density; one author per region; consistency held by the whole's reference sheet, the palette (`detail-plan.palette`) and every seam's `form`, and weakest at seams through fabric |
| a reconstruction of a continent, a coast, a valley system | **one region per landscape unit** — a valley, a bay, a ridge — bounded by water, ridgeline or cliff, each holding its few buildings | the player reads the landscape, not the buildings; building density per region is low, so a region's budget goes to ground; the natural edges are Lynch's | less detail per building than a castle region; many regions, so many workers; consistency held by a shared heightmap at the boundary and the terrain's own continuity |

**Where established practice informs this and where it stops** (**cited**): engines keep the whole as one persistent artifact and hand it authorial chunks — Unreal's World Partition stores one level in grid cells and places Level Instances by the world (research §1.4); the macro layout is drawn first and renegotiated while soft (The Witcher 3's pins on a map; Breath of the Wild's Kyoto overlay, §1.4); build teams fix per-region style and lay out plots before building (§1.6); kits fix standards before designers build (§1.3). None of these is a rule for sizing an authorial unit to one author's attention — streaming cells are sized to memory and draw distance, not to attention, and the only attested per-area ownership (Dark Souls, §1.4) held coherence in one director's head, which this pipeline does not have. So the sizing rule above is authored, the division lines are cited, and few test cases exist: how stable an agent's authoring is at a given size is what the nine-region level and the next campaigns measure.

## 10. The ADR consequence

ADR-0032 §2 reads: "`areas[]` remains the engine's assembly surface for library pools and is not a map route the skill presents." This spec removes `areas[]` and with it the pool assembly, which is the jigsaw mechanism ADR-0004 names. An Accepted decision is never edited; a superseding record is owed, and its number is allocated by the planner, not here. What it records: a map is placed by its site plan and nothing else; a prefab library is a library of pieces a place binds (`detail-plan.details[].piece`), never a pool a solver draws from; the jigsaw/template_pool mechanism of ADR-0004 is unused by the engine and is removed. Until that record exists, this spec is the only statement of the consequence, and criterion 10 holds the implementation to landing both together.
