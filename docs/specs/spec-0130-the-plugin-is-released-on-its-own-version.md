# spec-0130: The plugin is released on its own version — the entry serves the plugin's tag, the page pins a published engine, and a plugin release needs no engine release

- **Status**: Proposed
- **Ground**: the engine tree on `feature/the-plugin-has-its-own-version`, which carries this spec, read whole for: ADR-0038 (the decision and its sources); `.github/workflows/plugin-release.yml`; `tools/ci/check-plugin-release.py` and `tools/tests/test_check_plugin_release.py`; `tools/ci/check-skill-page.py` (rules 11, 12, 13, `own_version_rule`, `plugin_online`) and `tools/tests/test_check_skill_page.py`; `.github/actions/skill-page-objects/action.yml`; `.github/pins.toml` (`skill-page-engine`); `tools/ci/release-notes.py`, `tools/lib/release_notes.py`, `tools/ci/check-release-notes.py` and `tools/tests/test_release_notes.py`; `tools/tests/test_release_tags.py`; `RELEASE-NOTES.md`; `.claude-plugin/marketplace.json` and `.claude/skills/delvewright/.claude-plugin/plugin.json`; `docs/reference/skill-workflow.md`, `docs/reference/tools.md`, `docs/reference/front-end-standard.md` §2c. Every measurement below names the check that produced it.
- **What it is for**: a page fix merged after an engine release could reach creators only through an engine release of identical bytes, because the plugin's version was the engine's (ADR-0033). The plugin is releasable on its own. ADR-0038 records the decision; this spec states what holds for the engine developer and the release operator, and what judges each claim, so the capability can merge under CLAUDE.md's *no feature merges into `main` without an approved spec*.
- **Research**: ADR-0038 *Context* quotes the documentation it rests on, through `docs/reference/front-end-standard.md` §2c. Every rule below is marked **[cited]** with the ADR-0038 section or constitution line it rests on, or **[authored]** where this spec decides.
- **Numbers**: spec `0130`, ADR `0038`. No DW code, no `dsl_version`: nothing here changes what the compiler says or what a document says.
- **Supersedes, in words**: spec-0063 §8's rule table rows for the marketplace entry ("`ref` equals `[engine].ref`") and for `plugin.json` `version` ("moves on every pull request that changes any file under the plugin root"), and its criterion 4's reading of the entry. spec-0063 is a decision record and is not edited; this spec is the rule for those two rows.
- **Non-goals**: a change to how the engine or the format crate is released; a prerelease shape; a second plugin; a page walked against an engine other than its pin.

## 1. The version line **[cited: ADR-0038 §1]**

`plugin.json` `version` is the plugin's own number, strict `major.minor.patch` in `tools/lib/release_tags.py`'s grammar, moving only in the pull request that prepares a plugin release, forward from the newest `delvewright--v*` tag: patch for a fix, minor for a change in what a creator can do. A page edit under the released version is admitted and counted, never refused: `tools/ci/check-skill-page.py` rule 11 prints how many files this tree's plugin root is ahead of the tag by. A released version older than the newest, an unreleased version below it, and a version outside the grammar are reds. A checkout with no tag of the line is a refusal naming the fetch; `.github/actions/skill-page-objects` fetches `refs/tags/delvewright--v*` in every CI job that runs the gate or its tests, and `pin drift` fetches every tag.

## 2. The engine pin **[cited: ADR-0038 §2; ADR-0029 §2, §3, §6, §6a]**

`[engine].ref` names the engine the page is proven on and installs; the plugin's version does not derive from it. The unborn state stands for the pull request that prepares an engine release. A plugin release is refused at a pin whose engine tag the checkout lacks or whose Release the remote does not serve as published (`tools/ci/check-plugin-release.py`); rule 13 refuses a draft engine Release wherever `--online` runs.

## 3. The entry **[cited: ADR-0038 §3]**

The marketplace entry is a `git-subdir` source whose `ref` is `delvewright--v<plugin.json version>`, held equal by rule 12; `url` is `[engine].repo`; no `sha`, no `version`. The tag is immutable (ADR-0028 §9's ruleset) and the Release's archive is the same tree, so the entry resolves to the released plugin tree. `--online` holds the plugin's tag on both sides: unborn on both passes; present on both at one commit with a published Release passes; anything else is a red.

## 4. The release **[cited: ADR-0038 §4; ADR-0028 §4, §8; ADR-0036]**

`plugin-release.yml` takes a commit on `main` (default: the tip) and nothing else; `tools/ci/check-plugin-release.py --online` refuses before any write; `check-skill-page.py --online` runs at the commit; the notes are refused without an entry; the tag is written at the commit and the Release created `--latest=false`, read back. No engine release is dispatched, required or implied.

## 5. The notes file **[cited: ADR-0038 §6; ADR-0036]**

`RELEASE-NOTES.md` holds at most one entry per line, each line on its own clock; a line's preparing pull request writes its entry and drops published ones; an entry whose tag is written and whose version the tree still states passes.

## 6. The first release **[authored, from ADR-0038 *Consequences*]**

This branch prepares `delvewright 1.15.1` at `delvec--v1.15.0`: `plugin.json` 1.15.1, the entry at `delvewright--v1.15.1`, the `## delvewright 1.15.1` entry. After the merge the planner dispatches `plugin-release.yml` on the merge commit; no engine release precedes it.

## Acceptance criteria

Each criterion names the check that proves it and the perturbation that reds the check. "Green" is the state on the ground revision.

1. **A plugin release whose tree differs from the last plugin release only in skill files publishes with no engine release.** Check: `tools/tests/test_check_plugin_release.py::test_a_plugin_release_with_no_engine_release_passes` — a fixture with `delvec--v1.15.0` and `delvewright--v1.15.0` at one commit and a `main` commit moving only the page and the plugin's version to 1.15.1 passes the identity tool, which reads `delvec--v1.15.0` from the pin and asks for no `delvec--v1.15.1`; `tools/tests/test_release_tags.py::test_a_release_starts_only_by_dispatch` holds `plugin-release.yml` to a `commit` input and `test_each_release_derives_its_tag_through_the_grammar` holds it to the identity tool and refuses an `inputs.version`. Measured on this branch against the real remote: `check-plugin-release.py --commit HEAD --main HEAD --online` reports `stellarfeline/delvewright has no delvewright--v1.15.1`, `1.15.1 is above the newest release, delvewright--v1.15.0`, `delvec--v1.15.0 is published`. Perturbation red: `test_a_version_below_the_newest_release_is_refused` (1.14.9), `test_the_released_version_again_is_refused` (1.15.0), `test_a_tag_already_at_the_commit_is_refused`, `test_a_commit_off_main_is_refused`.
2. **A plugin release whose page pins an unpublished engine is refused.** Check: `test_an_unborn_engine_pin_is_refused` (the pin names `delvec--v1.16.0`, which no tag carries) and `test_online_refuses_an_engine_whose_release_is_not_published[draft|absent]` (the tag exists, the Release is a draft or absent). Perturbation red: those are the perturbations; the green arm is `test_online_passes_when_the_tag_is_unborn_and_the_engine_is_published`.
3. **A page change merged with no plugin version change is admitted, and the entry keeps creators on the released tree.** Check: `tools/tests/test_check_skill_page.py::test_the_newest_released_version_holds_with_its_drift_printed` — the version equals the newest tag's, the entry names that tag, a reference file is edited, no finding, and the drift count is printed. Perturbation red: `test_a_version_behind_the_newest_release_reds` (the version set to an older released one) and `test_an_entry_ref_that_is_not_the_plugins_own_tag_reds` (the entry moved off the tag the version derives).
4. **The marketplace entry resolves to the released plugin tree.** Check: rule 12 (`test_an_entry_ref_that_is_not_the_plugins_own_tag_reds`, `test_an_entry_carrying_a_sha_reds`, `test_an_entry_url_that_is_not_the_pins_repo_reds`, `test_an_entry_path_that_is_not_the_plugin_root_reds`) and rule 13's plugin arm (`test_a_released_plugin_tag_with_a_published_release_holds`). Perturbation red: `test_a_released_plugin_tag_at_another_commit_reds`, `test_a_plugin_tag_only_this_machine_has_reds`, `test_a_plugin_tag_that_appeared_on_the_remote_reds`, `test_a_released_plugin_tag_with_no_published_release_reds[None|draft]`. The tag's immutability is the ruleset of ADR-0028 §9, outside the tree, proved when it was written; `.github/actions/write-release-tag` refuses to move a tag.
5. **The version line is held on every run.** Check: `test_an_unborn_version_above_the_newest_release_holds` (the preparing state), `test_own_version_rule_reads_the_tags_it_is_given` (the three states over a handed list), and the binding `plugin release tag(s) of the line read`, 5 of 5 on this branch. Perturbation red: `test_an_unborn_version_below_the_newest_release_reds`, `test_a_version_outside_the_grammar_reds` (`1.0`), `test_a_leading_zero_in_the_version_reds`, `test_a_checkout_with_no_plugin_tag_cannot_judge` (exit 2 naming the fetch).
6. **A draft engine Release is refused by the shelf rule.** Check: `test_a_draft_engine_release_reds` — the same shelf answered `draft: true` reds and `draft: false` holds.
7. **The notes are per line and the release refuses without an entry.** Check: `tools/ci/check-release-notes.py` on this branch judges 1 entry (`delvewright 1.15.1`, unreleased, compared with the subjects since `delvewright--v1.15.0`), 0 findings; `tools/tests/test_release_notes.py::test_a_release_with_no_entry_is_refused`, `test_check_accepts_the_release_being_re_run_and_refuses_a_stale_entry`, and `test_the_plugin_notes_pin_the_marketplace_with_a_hash_ref` (the fixed-page command names the plugin's own tag). Perturbation red: the stale arm of the re-run test; an entry for `delvewright 1.15.0` on this branch reds as stale (observed while the entry was still present).
8. **The workflow class is unchanged.** Check: `tools/ci/check-release-publish-gate.py` green with `1 release verb(s) in a dispatch-only workflow with no registry act`; `tools/tests/test_check_release_publish_gate.py` over the updated fixture; `tools/ci/check-required-contexts.py` green with no context added or renamed. Perturbation red: `test_a_second_trigger_puts_the_dispatched_release_back_behind_the_gate`, `test_a_registry_act_puts_the_dispatched_release_back_behind_the_gate`.
9. **The pin registry holds one site.** Check: `tools/ci/check-pins.py` green with `skill-page-engine` bound by `check-skill-page.py` over its one site; `tools/tests/test_check_pins.py`'s release-pin arms. Perturbation red: `check-pins.py` reds on a `bound_by` that does not name every declared site (existing test).
10. **The documents say what the tree does.** `docs/reference/skill-workflow.md` *The release order*, `docs/reference/tools.md`'s rows for `check-plugin-release.py`, `check-skill-page.py`, `release-notes.py`, `check-release-notes.py`, `release_notes.py` and `release_tags.py`, and `docs/reference/front-end-standard.md` §2c are read against the tree before this spec is approved; no machine check beyond `check-doc-dupes.py`, `check-stated-counts.py` and the link check.
