# spec-0002: Compiler CLI contract

- **Status**: Approved (v0, owner-approved 2026-07-29)
- **ADRs**: 0001, 0004, 0006, 0009 (MC 1.21.11), 0010, 0011 (Rust-native)

The deterministic compiler (`crates/compiler`, binary `delvec`): staged DSL in,
datapack + server assets out. Rust-native per ADR-0011; command syntax validated
against the vendored 1.21.11 command tree; mecha re-validates output in CI only.

## CLI

```
delvec validate <campaign-dir>            # stages 1–5 schema + referential checks
delvec analyze  <campaign-dir>            # quest-graph reachability (ADR-0005 static)
delvec build    <campaign-dir> -o <out>   # full deterministic build
delvec schema   --stage <1..5|all>        # export JSON Schema (LLM authoring aid)
delvec --version                          # delvec x.y.z, dsl 0.1.0, mc 1.21.11
```

- `<campaign-dir>` contains `world.json`, `npcs.json`, `classes.json`,
  `quest-plan.json`, `quests.json` (spec-0001 envelopes; `stage` field must match
  filename).
- **Exit codes**: 0 ok · 1 validation failure · 2 analysis failure (unreachable
  quest/finale, deadlock) · 3 build failure (anchor/prefab resolution, emission) ·
  ≥10 internal error.
- **Diagnostics**: human-readable by default; `--json` emits one JSON object per
  line: `{ "code": "DW####", "severity": "error|warning", "stage": "<stage>",
  "path": "<json-pointer>", "message": "…" }`. Codes are stable API; the fixture
  matrix in CI asserts exact codes.
- `build` implies `validate` + `analyze`.

## Build output tree (contract)

```
<out>/
  manifest.json          # dsl_version, delvec version, mc version, input +
                         # per-file output SHA-256 hashes
  datapack/              # the campaign datapack: pack.mcmeta (94.1), advancements,
                         # scoreboard init, functions, dialogs, structures refs
  packtest-datapack/     # compiler-GENERATED PackTest suite for this campaign
                         # (mechanism assertions; consumed per spec-0003)
  server/                # server.properties, level config (fixed seed, void
                         # preset), eula-note; NO server jar (ADR-0010)
  critical-path.json     # bot walkthrough, see below
```

## World strategy (v0)

No pre-generated region files. The world is created on first server boot from a
**fixed void/superflat preset + fixed seed** (in `server/`); a compiler-emitted
bootstrap function (`#minecraft:load`, idempotent, guarded by a scoreboard flag)
places each area's prefab with **`/place template` at compiler-chosen coordinates**
and spawns/initializes NPCs, gates, and markers.

- Byte-identity (ADR-0006) therefore covers the entire `<out>/` tree — the shipped
  artifact contains no runtime-generated bytes. Runtime placement correctness is what
  PackTest + the bot verify (ADR-0005).
- **Scoping note (owner visibility)**: single-prefab areas make jigsaw unnecessary in
  M1 — `/place template` is the degenerate assembly. Jigsaw/`template_pool` assembly
  (ADR-0004 proper) lands in M2 with multi-piece layouts; the M1 seed-stability
  experiment from ADR-0006 moves to M2 with it. ADR-0004's prefab-library principle
  is unchanged.

## critical-path.json (contract output, versioned with dsl)

```json
{ "version": "0.1.0", "campaign_id": "hello-world",
  "steps": [
    { "action": "select-class", "class": "class/wanderer", "option_path": [0] },
    { "action": "talk-to", "npc": "npc/keeper", "pos": [8, 65, 12], "option_path": [1] },
    { "action": "reach", "anchor": "anchor/exit", "pos": [8, 65, 24], "radius": 2 },
    { "action": "assert-complete", "objective_scoreboard": "dw.campaign", "value": 1 } ] }
```

- Absolute positions are resolved by the compiler after placement planning — the
  harness (spec-0003) contains zero campaign knowledge.
- `option_path`: dialog button indices to click, recorded from the dialogue tree
  (the path to the option carrying the objective-completing effect).
- One step per critical-path objective, in a valid topological order.

## Determinism rules (ADR-0006, enforced here)

- All iteration over maps/sets is order-defined (BTreeMap or explicit sort).
- No wall-clock, hostname, locale, or absolute build paths in any output byte.
- All randomness (none needed in v0) derives from stage-1 `seed` via a named PRNG.
- `manifest.json` hashes make the double-build CI gate a one-line comparison.

## Acceptance criteria

- [ ] Double-build of the hello-world fixture → byte-identical `<out>/` trees
      (CI gate, every push).
- [ ] Exit-code + `--json` diagnostic-code matrix over the spec-0001 fixture suite
      matches expectations exactly.
- [ ] Emitted datapack loads on a headless pinned 1.21.11 server with zero errors
      in the log (tier-2 CI).
- [ ] Every emitted mcfunction line passes (a) our vendored-command-tree validator
      and (b) the mecha cross-check (ADR-0011) — disagreement fails CI.
- [ ] `critical-path.json` validates against its own published schema and is
      successfully executed by the harness in M1.
- [ ] A fixture with a deliberately unreachable finale exits 2 with code DW0201
      (reachability), proving analyze is not vacuous.
