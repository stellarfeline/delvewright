# spec-0121: A place is authored alone — each box's program is written by a fresh agent from a handout a tool derives, one place at a time

- **Status**: Approved
- **Ground**: written against engine `da769d0ed` (`origin/main`), read only — `Allocation` and `allocation()` in `crates/delvec/src/compiler/detail.rs`; the prepare → judge → write order of `delvec detail` in `crates/delvec/src/detail.rs` (every gate refuses before any file is written; the handed voids are written as `structure_void` after expansion); `.claude/skills/delvewright/skills/new-delve/references/detail.md` steps 1–4; `tools/ci/check-skill-page.py` rules 4, 7, 8, 16, 18 and 21; `docs/reference/skill-workflow.md` §2; spec-0058 (one verb details a place), spec-0098 §4 (the handout is produced by a tool and never typed), ADR-0012 (the creator is an agent; Claude Code is the runtime).
- **What it is for**: a map cut into boxes was detailed by one author holding every box and the whole design at once; on a large map that author stopped designing each place against its handout and generated every program from one geometry model, met every refusal of every place in one context, and recorded the run as broken down. The rule this spec executes: **each box's program is written by a new agent handed only that box's own necessary information and a summary of each adjacent box; a refusal is repaired by a fresh agent with the refusal added to the handout; the orchestrating session never edits a program.** It is settled, and it is how the real creation environment works — a creator running `/new-delve` does it because the page says so.
- **Numbers**: spec `0121`. No diagnostic and no `dsl_version` step: nothing a document says changes.
- **Non-goals**: several agents authoring at once (§7 says why one); partitioning a map into districts or authoring quests per place; a `delvec` verb for the handout (§3 says why not); a handout for a place that is a library piece or a form rather than a program (such a row is bound as `references/detail.md` already says, by the orchestrating session, with no agent).

## 1. The unit of work is one place, and its author holds nothing else

**Authored, on the rule above.** At step 9 of `/new-delve` the orchestrating session launches, per place, a fresh agent whose whole input is that place's handout (§2). The agent writes one document — `programs/<place stem>.json` inside the campaign — and checks it with the one verb that judges a place. It returns a short report. The orchestrating session confirms the verdict (§5), records the attempt (§6), and moves to the next place. It writes no program and reads none.

What the agent is handed is what spec-0098 §4 already calls the handout — what the whole gives a place, produced by a tool and never typed — plus the two things the rule adds: that place's rows of the campaign's design, and a summary of each adjacent box. What it is **not** handed is everything else: other places' programs, the design record, the site plan, the layout graph, the quest documents, other handouts. The handout quotes the rows of those documents that name the place; the rest is the whole's.

## 2. The handout

### 2.1 Derived, never typed **[cited: CLAUDE.md; spec-0098 §4]**

`scripts/handout.py <campaign-dir> <place> --engine <tree> --prefabs <dir>` writes the handout from the campaign on every invocation. The orchestrating session types nothing into it; an orchestrator that wants to tell a place's author more edits a document the handout quotes — the node's `note`, the seam's `form` — and runs the tool again. The handout is an input to nothing: `delvec detail` recomputes every obligation from the plan.

### 2.2 Where it lives

`<campaign>/.out/handouts/<place stem>/handout-<n>.md`, where `n` is one more than the handouts already there for that place — the attempt number, derived from the directory and never passed in. `.out/` is build output and is never committed; the handout is regenerable from the documents and the pinned engine, and `GENERATION.md` names the path (§6). A repair also writes `refusal-<n>.txt` beside it, the verdict verbatim.

### 2.3 Contents, each section with what it is derived from

| section | derived from | carries |

| header | the tool | the place, the campaign, the attempt number, the file's own path, the instrument (`delvec --version` and the binary's absolute path) |

The lessons of the stopped round are handout facts the author is told to read, in the sections above: a seam whose plane this place does not own means the ring on that side is not this place's (the frame excludes it); a neighbour's facade cells are voids owned by the neighbour; `roof.clipped` is spelled out as void runs; a ground place draws its own ground down to the terrain, so a quay's ring over the harbour floor is the quay's piece to draw. None of them is a new rule.

## 3. The tool is a skill script, not a `delvec` verb **[authored]**

Two candidates: a script under `.claude/skills/delvewright/skills/new-delve/scripts/`, or a `delvec handout` verb. The script, for three reasons.

1. **The page is held to the engine at its pin.** `check-skill-page.py` rule 4 refuses a `delvec` subcommand the page names that the clap surface at `[engine].ref` lacks, and the pin is a release tag. A verb added now could not be named on the page until the next engine release moved the pin, so the procedure would be unexecutable by the creator the page ships to for a whole release cycle. A script ships with the page and is proven by the same gate on the same day.
2. **Half the handout is dispatch material, and dispatch is the runtime's.** What the agent may read, what it never runs, the exact commands with the instrument named, the refusal of the last attempt, the shape of the return — this is how an agent is briefed inside Claude Code (ADR-0012), never a fact about a campaign. The engine's half already exists as `delvec allocation`, computed once, and the script embeds its output unchanged. A verb would put a brief in the compiler.
3. **It errors on a mistake where the mistake is entered.** The script takes a campaign directory, a place, the engine tree and the prefab directory — no number and no free text. It refuses a directory with no `world.json` (exit 2); an engine tree with no `docs/reference/grammar.md` or a prefab path that is not a directory (exit 2); a `delvec` its shell cannot run (exit 2); a place the plan allocates no box to, naming every place it does (exit 1); a campaign `delvec allocation` refuses, in delvec's own words (exit 1); and a place whose program already passes `delvec detail` (exit 3) — there is nothing to author, and a handout would send an agent to rewrite a program nobody refused. The refusal a repair hands on is never passed in: the script runs `delvec detail` on the program it finds and embeds the verdict, so the refusal is of this place, of this program, from the one verb that judges it.

What a verb would have bought — a typed reading of the campaign — is not lost: every number in the handout is the allocation's own JSON, copied and never parsed into anything but a copy, and every design row is quoted from the document that holds it.

## 4. The launch, in Claude Code **[cited: ADR-0012; the runtime's Agent tool]**

The orchestrating session launches the agent with the **Agent tool**, `subagent_type` `general-purpose`, and a prompt that is exactly the one line the script prints: `Read and execute <handout path>. Report, then exit.` **Never a fork**: a fork inherits the session's whole context — every other place and the design — which is the one thing the rule forbids handing over. The handout is handed by path rather than pasted so that the agent reads it byte-exact and the orchestrating session never holds the allocation in its own context: it cannot author what it has not read.

The agent **may read** its handout, its own program, the authoring references the handout names, and the grammar corpus through `delvec grammar list` and `grammar show`. It **may run** `delvec allocation <campaign> <place>` (the same facts, asked again), `delvec grammar expand` at the frame to look, the render commands the *new pieces* reference names, and the check. It **writes** one document, `programs/<place stem>.json`, and where it emits that document from a script, the script beside it under `design/generator/` as provenance. It **never** reads another place's program, the design record (`DESIGN.md`, `GENERATION.md`, `design.json`, `design/`), the site plan, the layout graph, the quest documents or another handout; never edits any other document; never runs `delvec detail --all`, `delvec build`, a server or `git`; never retypes a handed number as a literal; never weakens a check or rerolls a seed. Scratch goes under the handout's own `work/` directory, never `/tmp`.

**The check helper is `delvec detail <campaign> <place>`**, run by the agent as often as it likes. It binds the handing into the program, expands at the frame, writes `structure_void` at every handed void, runs the grammar gates, the admission audit, the light probe and the bindings check, and refuses with the cause named **before any file is written** (spec-0058 §2.2, steps 1–7); at exit 0 it has written the piece and the plan row, which is the finished state. `grammar expand --region <frame>` is for looking — the program's `handed/…` defaults are the handed values, so no `--param` is typed — and it sees neither voids nor seams, which is why it is not the check. One fact the handout states because no gate says it: a cell the program paints at a void is replaced, not refused, so nothing put there survives and nothing may depend on it.

## 5. The return, and how it is verified

The agent's report is short: the place; the program's path; the exit status of its last `delvec detail` and that run's summary line; what it built, in three lines; any capability it needed and the grammar lacks, in one sentence. No transcript, no proposal about another place.

The orchestrating session then runs `delvec --prefabs "$DELVEWRIGHT_PREFABS" detail <campaign> <place>` itself. **Exit 0 is the verdict**, and a second run after a green one moves no byte (ADR-0006), so the agent's green and the orchestrator's agree or the difference is a finding. Any other exit: the session runs `scripts/handout.py` again — which runs `delvec detail` on the program the agent left, captures the refusal, and writes `handout-<n+1>.md` with it — and launches a **fresh** agent on that handout. The refused program stays in place: the new agent repairs it, and starts over only when the program is beyond repair.

**Three consecutive refusals of one place naming the same diagnostic code** mean the cause is upstream of the program — the plan's box or seam, a `form` no program can answer, or a capability the grammar lacks. The session stops launching agents on that place, says so in the run with the three verdicts, and acts on the cause: a plan edit (which re-details every place, `references/detail.md` step 4) or the page's own rule for a missing capability — say what is missing and offer the closest authorable alternative. Launching a fourth agent on the same refusal is the loop the page's three-strikes rule already forbids.

## 6. What `GENERATION.md` records

One table, **Detail**, written by the orchestrating session, one row per attempt: the place; the attempt number; the handout's path; the agent's token reading and its duration, as the Agent tool's completion reports them; the diagnostic codes of the refusal that attempt repaired (none on a first authoring); the `delvec detail` exit the session confirmed. The handout path names a regenerable file, and the table says so once above it. No date, no model name, no agent id (CLAUDE.md, *Privacy in repo artifacts*).

## 7. One agent at a time **[authored]**

Places are authored **serially**: one agent runs, returns, is verified; the next launches. Three reasons, and the first alone decides it. `delvec detail` writes the row into the campaign's `detail-plan.json`, writes the piece into the shared prefab directory, and judges the whole as that run would leave it; two agents checking at once race on both files and judge a whole the other is changing. Second, the only way to run two safely is one worktree and one prefab directory per agent with a merge after — machinery whose cost nothing here has measured, and which the rule did not ask for. Third, the handout tells an agent which neighbours are already detailed and as what; under parallelism that fact is stale the moment it is written.

The order is the **critical path from `entry`**, then every other place in the order `delvec allocation --all` prints them, scenery last. The party meets the spine first, so a spine place that no program can answer is found before the rest of the map is spent on it.

## 8. The skill

`SKILL.md` step 9 names the procedure as mandatory and the three things it adds; `references/detail.md` carries the body: the script, the launch, the agent's permissions, the check, the verification, the repair loop, the stopping rule, the record, the order. The page carries the Agent call shape and no model tier; `docs/reference/skill-workflow.md` §2 records that the page now carries this one dispatch, and why (the creator's own session is where the agent runs). `docs/reference/tools.md` lists the script under the plugin's scripts.
