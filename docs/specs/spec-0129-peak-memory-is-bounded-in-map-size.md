- **What it is for**: a build held the whole map in memory several times over, and the largest holdings grew with the site region's volume or with the cells a body can reach — the town (95 places, an 86 M-cell region) peaked at 14.06 GiB, and growing its region by 57 M cells cost 1.86 GiB more. The ruling is that peak memory is about constant in map size: a fixed working set, every whole-map stage reading and writing the map in bounded chunks, and the engine stating what a build costs before it starts; the hosting side meets the stated cost and the engine never refuses a map for its size. ADR-0037 records the decision, the established practice it rests on and the measurement of each step. This spec states what holds for the engine developer, what judges each claim, and what the branch still owes — so the feature can merge under CLAUDE.md's *no feature merges into `main` without an approved spec*.
- **Research**: ADR-0037 *Established practice* is the record (the game's own sectioned chunk format, per-chunk light flooding with border spill, HPA* over a portal graph, external-memory BFS, streaming connected components, paged sparse-volume leaves). Every rule below is marked **[cited]** with the ADR-0037 section or constitution line it rests on, or **[authored]** where this spec decides.
- **Numbers**: spec `0129`. No DW code: nothing here changes what the compiler refuses or warns. `dsl_version` does not move: nothing here changes what a document says. One new file in the output tree, `validation/resource-cost.json`, indexed by `manifest.json`; the files whose counts move are declared in §1.4.
- **Non-goals**: a faster build (CPU time is recorded beside every row and not judged here); a budget a host sets (§1.2 refuses it); a map refused or truncated for its size; a weaker proof anywhere (§1.4: every exact answer stays exact); a second budget, spill policy or scratch location for a structure that pages next (§1.2, §1.3: it registers with the one).

## 1. The store and the budget

### 1.1 One section store **[cited: ADR-0037 §1]**

The assembled world is one section store (`compiler::sections::SectionMap<BlockState>`, as `blockstate::BlockMap`): 16 × 16 × 16-cell sections by section coordinate, each a palette of the states it holds and one index per cell — a byte while the palette holds at most 255 states, two after, the palette compacted before the index widens. A section nothing wrote is absent and reads as what the level generator lays there. The store answers what a `BTreeMap<[i32; 3], _>` answers and iterates in the same cell order, so no consumer observes the sectioning. The judged copy (`Assembled::judged_within`), the write judge's stores, the review world's block map and every whole-world `CellMap<V>` (the light model's blocks, the nav world's `partial` and `material`) are stores too. The whole assembly is one write program laid section column by section column (`assembled::write_by_section_column`), the judged copy is taken section by section, and the settle runs per section column, so the working set while the world is assembled and cut is one section column of each store. Every build prints `world store: N placed cell(s) in S section(s) of 16 x 16 x 16, B byte(s)[; the judged copy …] (ADR-0037 §1)`.

**The judged world is a second store** **[cited: ADR-0037 §1; the paged copy accepted as built]**: the judged columns and the barrier wall are a `BlockMap` of their own (`Assembled::judged_within`), taken section by section, its arrays paged under the one budget like the whole's. On the town it is 3,900 sections, 16,360,704 bytes of records, against a masked view every reader of the judged world would take; the copy is what holds, and a mask is not owed.

### 1.2 One resident budget, from needs the structures measure **[cited: ADR-0037 §1]**

One budget module (`nav::world::reach::budget`) is the only place a working set is summed or a holding given up. Every structure that pages — the reach graph's edge lists, its snapshot pages, the section stores' index arrays — states a `Need` and registers; it adds no budget of its own. A need is the working set the structure's walk has had to hold, never a number a host sets: the lists' is the 3 × 3 ring of reach chunks at the largest any list has decoded, with the ring's buffered pushes; the snapshot's is four 3 × 3 rings of the tallest window's pages; the stores' starts at a 3 × 3 × 3 ring of sections at the wide index (221,184 bytes) and is raised as the build runs — a read-back within one turnover of the need is a re-reference: fewer arrays came resident over every store (made or read back: the arrivals clock, which the stores share) since the array was given up than the need holds, and it was given up under the need now stated; a sample of 64 read-backs of which half or more are re-references doubles the need, until the walk's working set stays. An array given up long before is read back cold however few cells of it the walk touches, so a sliver written into a section placed long before, a second sequential pass, a store another stage's growth pushed out, a copy's first read of a shared record, and an array given up under an earlier need raise nothing. The budget is the sum of the needs stated. Past it, the structure that just grew gives up its least recently used holdings first, down to three quarters of its own stated need and no further, then every other is asked, the stores never below three quarters of theirs, until the total stands at three quarters of the budget: no structure is emptied for another's growth. What any structure answers never depends on what is resident. A run that took a closure prints `reach budget: R byte(s) resident at the end, under one budget of N byte(s), the sum of the working sets stated: … (ADR-0037 §1)`; a run whose stores held a section prints `world store pages: … the need raised T time(s) for a walk found thrashing, to N byte(s); B byte(s) in the scratch file in regions of 8192 byte(s), at most R of them holding a live array at once; at most A array(s) alive at once over every store (ADR-0037 §1)`, and each raise prints `world store need: raised to N byte(s); …` as it happens. The arrivals clock counts every thread's arrivals, so where walks run beside each other the raises a run makes are the schedule's (§1.4 says what reads them).

### 1.3 Scratch files: one policy, one place **[cited: ADR-0037 §1, *Consequences*]**

A holding given up is written to a scratch file in the system's temporary directory, never under `-o` — the output tree is the deliverable the determinism gates hash — and read back on demand, positionally, while writers append. One policy for every spill (`reach/spill.rs`): a scratch file that cannot be opened is no file and the structure holds its records in memory; one that was opened and then refuses a write or a read back stops the run with a message naming the file, the operation, the error and the bytes written. **The stores' scratch file holds one region per array alive** (`sections::Region`): every region is one size, the wide record's (8,192 bytes); an array keeps its region across read-backs and give-ups — given up unchanged, its record stays and nothing is written; changed, the record is rewritten into its own region (`Spill::write_at`); a region a copy shares is never rewritten while the copy holds it — and a region whose last holder drops it serves the next array before the file grows; so the file's size is bounded by the most arrays alive at once over every store and never by the give-ups a run made. **The reach graph's spills give a dropped record's room back** (`spill::Extent`): a list chunk rewritten whole, a list or node table dropped and a variant the bank lets go free their bytes, the next record that fits takes the smallest free range, and a free range at the file's end shortens the file; the snapshot's pages and the stores' regions are kept for the file's life, and a kept region is never reached by the room given back (`spill::tests::a_region_kept_for_the_files_life_is_never_reached_by_the_room_given_back`; the stores' file keeps what it wrote, in whole regions: `the_scratch_file_holds_one_region_per_array_alive`). A build's disk is the map's size there. The bank file a run keeps with a campaign (`DWBANK03`, read and written chunk by chunk by `delvec detail` and by a run that sets `DELVEC_REACH_CACHE`) is a persisted artifact under the campaign, not a scratch file, and is outside this rule.

### 1.4 Neither the budget nor the chunking is an input to any emitted byte **[cited: ADR-0037 §1, §4; ADR-0006]**

The section side (16, the game's constant; it has no knob, so no proof varies it, and the store answering what a map answers at that side is the proof that it is unobservable), the reach chunk side (`chunks::SIDE`, 32 columns), the budget in force and what is resident at any moment decide residency and disk traffic and nothing else: every exact answer — the reach closure, the leak floods, the light per region, the write judge — is the answer the unchunked form gives, and the output tree is byte-identical to the engine before the store, file by file, with the exceptions declared here and nowhere else. **Declared**: every launch is judged against the closure at the start of its round rather than against what earlier batches of the same round had grown, so the reached states are the same set and the edges, launches and arcs the binding counts move. Against `main` @ `9d83c48c0`, on the town and on the widened town alike, the rest states stay 193,101 (142,816 standing, 8,699 afloat, 41,574 submerged, 12 holding), the edges move 2,832,195 → 2,974,762 (walk 593,547 → 597,568, fall 404,261 → 436,646, jump 1,544,857 → 1,651,018; dive and climb equal), the launches simulated 140,079,485 → 149,153,846 and the template arcs credited 83,229 → 86,855. The output bytes that differ from `main` for this reason are `validation/reach-graph.json` (those five figures and nothing else), the added `validation/resource-cost.json`, and the `manifest.json` lines that index them. The terrain's ground in the sea's band is no water (`World::ambient_water`: a solid, a 1.5-tall barrier, a fence gate, lava or a killing volume the assembly wrote is no ambient water; water it wrote stays water) is `main`'s own rule at `9d83c48c0`, so it moves no byte between the two; against a `main` without it, it moved `validation/reach-graph.json`, `validation/leave-proof.json` and `validation/sea-seepage.json` (on the town the rest states 1,366,129 → 193,101), and the rows before it could pass `DW0921` on a campaign that should have been refused. The counts that depend on the chunk side (`reach portals:`, every end-of-run line of §1.2) are written to stderr only. A build at any thread count writes the same tree (`tests/thread_count.rs::the_output_is_the_same_at_every_thread_count`, which normalises the machine's own lines — §9 names them — and asserts the count of lines it touched equal).

## 3. The engine states a build's cost before it starts **[cited: ADR-0037 §3; CLAUDE.md *Host hardware never caps a capability*]**

Before the whole-map stages start, `delvec build` and `delvec detail` print one line, `resource cost: …` (`compiler::cost::ResourceCost`), computed from the documents and the store alone — the site plan's region, the horizon, the judged columns, the reach window those give through the snapshot's own rule (`nav::window_box`), the store's sections, the sections a build write covers (`Reached::sections_written`) and the sections the path's region writes cover (`cost::region_sections`) — and `delvec build` writes the same numbers as `validation/resource-cost.json` with `"computed_never_measured": true`. The line states: the reach window at most and its reached and plain-sea bitmaps; the chunks across it at the chunk side and their face cells; the rest census (§3 of ADR-0037: per column, the cells a body can rest in at most — one standing candidate over every surface, every climbable cell, every fluid cell and every cell of the sea's band holding no ground) and the bounds it gives — the states at most, the most nodes one chunk holds, the lists' largest chunk at most by its candidates' envelopes, the portal edges at most in one closure; the working set before any walk (the stores' ring + the snapshot's pages + the lists' buffered pushes); the summaries at most (face labels: judged sections × 6 × 128; configurations: the region writes + 1); the stores' scratch at most: one region of 8,192 bytes per array alive at once, the arrays alive at most being the whole's and the judged copy's sections, the write sequence judge's four stores over the written sections, and each configuration's region sections (`ResourceCost::arrays_at_most`); and the reach graph's scratch at most (`ResourceCost::reach_scratch_bytes`, `nav::scratch_bound_of`): per configuration, the snapshot's pages over the window (⌈cells / 4096⌉ × 4096 × 6 bytes), the two node tables (an entry per rest candidate in each, the cell-relation edges in one and every edge of the candidates' envelopes in the other, at the encoder's record sizes), one closure's two lists (a record per edge in each, one chunk's once more) and the bank's file, which is the cap the build sets on what the banks keep (`ResourceCost::bank_cap`, `nav::set_bank_cap`, before the proofs run): the tables and the lists again — the bank is a cache, a variant that would pass the cap is not kept and the next world that asks re-flies the node, and no output byte reads it (`reach::tests::a_bank_past_its_cap_keeps_no_more_and_answers_the_same`) — times the configurations — a bound on the three files together, which the `reach scratch:` line measures as each file's longest; what the terms do not count by name — the variants' worlds, a second closure over one configuration, a node's second table entry under other quadrants — is covered by their slack, held by test on generated cases (`reach::tests::a_second_world_and_a_second_closure_stay_under_one_configurations_bound`) and on the gallery (the baseline job's gate), and the ledger says by which term under `reach_graph_covered_by_slack`. Every `at most` figure is an upper bound a build cannot exceed; the working set before any walk is a floor the budget starts at, not a bound. The ledger holds nothing measured, so two builds of one campaign write one file; what a build reached is the end-of-run lines of §1.2 and `reach lists:`, `reach portals:`, `reach states:`, `reach graphs:`, `reach snapshot:`, `reach closures:`, written nowhere in the output tree. The hosting side meets the stated cost and reads the measured lines for what a build took; the engine does not refuse a map for either.

**[authored]** The relation between a computed bound and the figure it bounds: each `at most` figure is at least the measured figure, on every map; and at most four times it where the plan and the store decide the figure — the bitmaps, the snapshot's pages, the rest states, the configurations and the scratch file. **Declared as a loosening, in those words**: the lists' largest chunk, the portal edges and the face labels are not held to four times their measure, because what a build reaches there is decided by flying the launches and flooding the air, which no figure of the plan and the store reaches (ADR-0037 *The stated cost tells the truth, measured*: on an open floor of 1,024 cells the nodes hold 30.7 edges on average and 69 at most against an envelope of 121 columns, a node flying only the launches that can reach an unreached rest cell; a section's air is one component where the bound allows 768); each stays bounded by the census's envelope (the lists, the portals) or by the judged sections (the face labels), is at least its measure on the town, the widened town and the gallery, and its factor is stated per figure in ADR-0037. The premise variants and counterfactuals the proofs build beside the configurations (`reach graphs:`) are declared as not counted by the configurations figure nor by the scratch figure, each owning at most the region sections it writes.

## 4. What the tree proves, and how **[cited: ADR-0037 §4]**

Each proof is a test in the tree, named with what it counts; a perturbation named beside it is one the record ran and restored from a copy.

- **No answer of the reach graph depends on its chunk side or the budget**: `reach::agreement::no_answer_depends_on_the_chunk_side_or_the_budget` — every world of `invariance_worlds()` (seventeen: twelve generated courses, the Bell yard, the jetty, the garden, the ladder cliff, the reef) asked of a closure kept in chunks of sixteen columns, of seven, and of two under a budget of one byte, and of one over a snapshot paged to a single resident page; every state, every state's successors and predecessors in order, the flags, the counts and both node tables equal; the records read back equal the edges counted at join; the test refuses a zero count of holding states and of two-column-face crossings. Beside it: `the_chunked_closure_is_the_one_every_launch_gives` (the closure equals flying every launch of every node, at two sides), `a_walk_by_chunk_answers_what_a_plain_walk_answers`, `the_route_tree_by_chunk_is_the_one_search_gives`, `the_portal_edges_are_the_edges_that_cross_a_chunk_face`. Perturbations: skipping a chunk's buffered records in `Chunk::load` → red; reversing each cell's list → red at side 2; dropping the cross-chunk push → red on the jetty; flipping the route chooser's tie → red; dropping `visits.joined` → red; a slab left unsorted → red.
- **The summarised sea is the closure expanded cell by cell**: `the_summarised_sea_is_the_closure_expanded_cell_by_cell` (every invariance world of the summarised closure against the closure that expands every water cell; the jetty's 2,736 plain cells in one component, the reef's 2,722 in two), `a_plain_sea_cell_is_the_one_expand_gives` (every cell of the jetty's and the reef's windows: 5,458 plain for the rule and for `expand`, 2,677 submerged cells refused by both). Perturbations: the 3 × 3 × 2 tops ignored → red; five dives counted → red; the plain neighbours left out of the predecessors → red; the boundary not handed to the frontier → red; `States::plain` always false → red.
- **Each store answers what a map answers**: `chunks::table_tests::a_list_kept_by_chunk_answers_what_a_map_answers` (the rewrite branch and a copy mid-stream under a budget of one byte), `a_table_keyed_by_chunk_answers_what_a_map_answers`, `states::tests::the_states_answer_what_a_map_of_them_answers`; `sections::tests::a_section_store_answers_what_a_map_answers` — 60,000 generated inserts and removes over three cell pools, 300 distinct values so dense sections outgrow the one-byte index, a copy mid-stream, the whole iteration and 20 boxes read back after every 5,000 edits against a `BTreeMap`, under the default budget and under a budget of one byte; `a_palette_forgets_the_values_no_cell_holds`; `an_array_given_up_reads_back_as_written_in_both_forms`; `a_copy_shares_its_arrays_until_one_side_writes`. Perturbations: the local index y-leading → red; the box clipping z one short → red; the ly advance keeping its section → red; the wide record decoded as narrow → red; a copy's record shifted by one byte → red; an array given up but kept resident → red; a shared array written in place → red.
- **The scratch file holds one region per array alive**: `sections::tests::the_scratch_file_holds_one_region_per_array_alive` — a generated store written, read, copied, cut and grown over twelve rounds under a budget of one byte; the regions the thread appended at most the arrays its stores held alive at once (1,264 against 1,264), against 26,127 give-ups, and the give-ups at least four times the appends. Perturbations: a record appended at every give-up (the old shape) → 5,657 appended, red; a dropped array's region never serving the next → 3,582, red.
- **The need is a measurement of re-reference**: `sections::tests::a_walk_found_thrashing_raises_the_need` (a store read at random over twice the need raises it until the working set stays), `a_sparse_walk_over_a_spilled_store_is_cold` (a store four times the budget walked once a round raises nothing), `a_store_another_stages_growth_pushed_out_is_read_back_cold`, `an_array_given_up_under_an_earlier_need_is_read_back_cold`, `the_capacity_is_the_need_in_arrays`. Perturbations: the thrash comparison inverted → red; the clock standing still → red; the generation check dropped → red.

## 5. How a memory claim is measured **[cited: CLAUDE.md *Measurement doctrine*; ADR-0037 *The closures, measured* and after]**

A peak is measured with two instruments that share no configuration: GNU `/usr/bin/time -v` (the kernel's maximum resident set from `wait4`, and CPU time) wrapping `tools/maintenance/rss-sample.sh` (VmRSS and `/proc/<pid>/io` once a second beside the timestamped stderr, so a stage line stands beside the resident set at that second); the two peaks are compared and the one that disagrees is the instrument failing; a spike shorter than the sampler's second is the kernel's figure and the sampler's is the plateau. The second method for the output is the file-by-file comparison of the trees two engines write (`tools/ci/tree-digest.py --compare`, or per-file `sha256` with the count of files stated), which shares nothing with either memory instrument. Each engine is force-rebuilt from its revision with cargo's exit status asserted and its binary named by revision; two runs of each map on each engine; the town and the widened town (the town's region grown by 100 cells on every horizontal side, same 95 places, derived from the town by the measurement's own script) are the two maps, and the difference between them is the figure that says whether memory grows with the region. CPU time is the timing claimed; wall time on a shared machine is recorded and not claimed, and the machine's load is read before each run. A measured figure goes in the commit body and the record, never in the output tree or the reference.
