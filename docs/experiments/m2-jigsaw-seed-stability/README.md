# Experiment: jigsaw seed-stability (M2, gates ADR-0004)

**Question.** Does vanilla jigsaw generation driven by `/place jigsaw` with a
fixed world seed on the pinned 1.21.11 server produce an *identical* layout on
every run? This is the highest-stakes unknown in M2: it decides whether ADR-0004
(prefabs assembled by vanilla jigsaw with compiler-controlled seeds) holds, or
whether its GDPC-style offline-assembly fallback is required (ADR-0004 revisit
trigger #2; ADR-0006 "world determinism … verified by test in Milestone 1").

## Verdict

**DETERMINISTIC (`/place jigsaw`, fixed world seed + fixed position, pinned
1.21.11).** Layout is a reproducible function of the world seed and placement
position. Same seed + same position → byte-identical layout across independent
fresh server processes; different seed → different (but internally reproducible)
layout. ADR-0004 stands as written; the GDPC fallback is **not** needed.

## Method

Datapack-only, no compiler. Four tiny 7×5×7 structure pieces (`room_iron`,
`room_diamond`, `corridor`, `deadend`), each enclosed and lit, each carrying a
distinct **marker block** at its centre (iron/diamond/redstone/emerald block)
plus a `lapis_block` "nose" one cell toward its entrance (so the marker set
encodes piece **type**, **position**, and **orientation**). Pieces expose jigsaw
connectors: a female `entrance` (north, `pool = minecraft:empty`) and male `exit`
connectors (`target = dwexp:entrance`, `pool = dwexp:main`). The weighted pool
`dwexp:main` (iron 2 / diamond 2 / corridor 3 / deadend 1) makes every connector
an RNG choice, so any RNG difference diverges the layout.

Per run (each a **fresh OCI container = fresh world**, superflat void, itzg base
= `delvewright-base`, `SEED` set):

1. `forceload add -56 -56 56 56`
2. `place jigsaw dwexp:main dwexp:entrance 6 <pos>`
3. `function dwexp:scan` — a generated function that, for every cell in a
   ±48 box at the marker layer, logs `M <type> <x> <y> <z>` for each marker block.
4. Fingerprint = `sort -u` of the logged marker lines; SHA-256 of that.

Layout export uses the marker-scan-to-log route (not `/clone`+structure-save:
Java has no command to *save* a structure — only `/place template` to load one).
`maxCommandChainLength` is raised so the scan runs in one tick; the scan box is
sized to keep it under the vanilla 65536-command function cap.

Reproduce: build the image (`Dockerfile`, bakes `datapack/` with structures from
`generator/`), then run `harness.sh` (test A + B) and `harness2.sh`
(order-independence). Structure `.nbt` are regenerated by the committed generator
(`cargo run --manifest-path generator/Cargo.toml -- datapack`), not stored as
binaries. The scan function is generated with:
`for y in -60: for x in -48..48: for z in -48..48: for each marker: emit "execute if block x y z <marker> run say M …"`.

**Known defect in the recorded method** (found 2026-08-11, NOT
corrected here). Both harnesses set `gamerule maxCommandChainLength 2147483647`
during boot. 1.21.11 renamed that rule to `max_command_sequence_length`, so the
legacy spelling answers "Incorrect argument for command" and changes nothing —
and both harnesses discard the reply, so neither run could notice. The scan
therefore ran at the vanilla default limit (65536) in every run recorded below.
It does not disturb the verdict: the limit applied identically to every run, and
the comparison is between runs, but the scripts are left exactly as they were
executed so the recorded result stays reproducible from the recorded method.
`tools/check-live-commands.py` excludes `docs/experiments/` for that reason.

## Evidence (`evidence/runs.txt`, full harness output)

| test | seed | pos | fresh worlds | markers | SHA-256 (fingerprint) |
| ---- | ---- | --- | ------------ | ------- | --------------------- |
| A    | 20260729 | `0 -59 0` | **6 / 6 identical** | 28 | `af51546b8d9febcde2b5a95809f05d494f92c35d8449b99189170b983244fd90` |
| B    | 99999999 | `0 -59 0` | **3 / 3 identical** | 46 | `b41133ee7b789d24729f00c3dc19a035e70b9119bc8695d08304b039ff564b40` |

- **A:** six independent fresh containers, same seed+pos → one hash. Reproducible
  across server processes.
- **B:** different seed, same pos → a *different* hash, itself stable across 3
  runs. Layout **depends on the world seed** (not position-only or constant).
- **Order-independence (`harness2.sh`, `evidence/order-independence.txt`):**
  placing at position Q gives the **same** Q fingerprint
  (`4b5e10365a8b1c6490c7593e767b5251c5b539d47eaf0f4c5ed37282d1b0b6d0`) whether Q
  is the 1st placement (alone) or the 2nd (after a placement at P). So layout is a
  **pure `(world seed, position)` function** — it does *not* depend on the shared
  RNG-stream position / command order. The compiler may place structures in any
  order and each is independently reproducible.

## What is deterministic, precisely

- `/place jigsaw` derives its randomness from the **world seed** (a fresh world
  generated from the same seed reproduces the layout exactly), keyed by placement
  **position**. Different positions in one world give different, independently
  reproducible sub-layouts.
- Determinism holds **across separate server processes / containers** of the
  pinned 1.21.11 image — the property ADR-0006 requires ("same DSL + same seed →
  byte-identical world").

## Compiler guidance (ADR-0004 / ADR-0006)

- The delve world is created fresh at first boot from the campaign seed
  (spec-0001 `content.seed`); jigsaw assembly at that seed is reproducible, so
  the compiler can drive layout via jigsaw and rely on it byte-for-byte.
- **Two viable deterministic invocations:** (a) `/place jigsaw` issued at a fixed
  point in first-boot (what this experiment used), or (b) a worldgen-registered
  jigsaw structure + structure-set generated at chunk generation — the canonical
  seed+chunk-derived path, independent of any command timing. Prefer (b) where a
  structure can be pinned to a known chunk; both are seed-deterministic here.
- **Template pools must be present at world-load time** — `/reload` does not
  refresh worldgen template-pool registries (confirmed). The shipped delve bakes
  the datapack so pools load at first boot.

## Fallback status (ADR-0004)

Not triggered. Had `/place jigsaw` been non-reproducible, the fallback is:
compiler-side layout — the compiler picks pieces/positions with its own seeded
PRNG and emits N `/place template <piece> <pos>` calls, using jigsaw only as a
connectivity *vocabulary* (socket names). That fallback stays inside ADR-0003
(vanilla `/place template` only, no mods) and ADR-0006 (all randomness from the
one campaign seed through the compiler's PRNG). Recorded here for completeness;
current evidence does not require it.
