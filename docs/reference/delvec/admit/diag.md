# `delvec::admit::diag`

The reference page for `crates/delvec/src/admit/diag.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../compiler.md#5-diagnostics-catalog).

## Diagnostics

### DW07xx — asset, render and authoring tooling (spec-0007; `delvec` subcommands)

The prefab, schematic, grammar, render, viewer and `fmt` subcommands of
`delvec`, each with its own exit-code scheme; diagnostics to **stderr**.
Catalogued here so the DW namespace is complete and CI-checked. Codes are
numbered by DOMAIN rather than by subcommand — `DW0724` sits in the
visual/render range and `DW077x` is `delvec fmt` (§9) — because a code names a
rule, and the rule's domain is the more useful thing for the number to say.

| Code | Tool | Meaning |
|------|------|---------|
| `DW0730` | `delvec prefab` | Audit: a palette block, or a template entity's kind, is not in the allowlist. A template's `entities` may carry only the kinds the allowlist's entity list names — by default the three item holders (`minecraft:item_frame`, `minecraft:glow_item_frame`, `minecraft:armor_stand`, spec-0111 §3.1); a file's `allow_entities` replaces it as `allow` replaces the block list. For a block: The allowlist is a list of names **at the pin**, so the id it judges is the one a 1.21.11 server will hold after datafixing — not the one the bytes spell. For a template at the pin those are the same id; for a pre-pin template whose palette names a block the game has since renamed, the entry is resolved through `BlockRegistry::loaded_id_at` first and the diagnostic names both ids (`minecraft:chain`, written at DataVersion 2975, is judged as `minecraft:iron_chain`). An id the pin does not have and the rename table cannot reach is judged as written, which refuses it: resolution never widens the list. **The message names where the block is had instead**: eight refused ids have a first-class DSL surface (`lever`: a trigger's or `interact` objective's `prop`; `note_block`, `jukebox`: a `play-sound` effect; `piston`, `sticky_piston`: a `set-block` or `fill-region` effect; `spawner`, `trial_spawner`: a `waves[]` entry fired by `spawn-wave`; `dispenser`: a `traps[]` `volley` payload), and each message carries its surface; every other refused id says that no DSL surface stands in for it. |
| `DW1036` | `delvec prefab` | Audit (spec-0111 §6.2, `admit::entities::judge`): a template's item holder carries a key the engine owns — anything outside its kind's scene properties (a frame's `Facing`, `ItemRotation`, `Invisible`; a stand's `Rotation`, `Pose`, `Small`, `ShowArms`, `NoBasePlate`, `Invisible`): its `Item` or `equipment`, `Fixed`, `Invulnerable`, `ItemDropChance`, `DisabledSlots`, `Marker`, `Tags`, `UUID`, a position key, or any other. The message names the entity, the key and what the engine sets or derives in its place; the remedy is to remove the key and declare the item by a fill (`loot` or a `collect`'s `holder`) on the anchor at its cell. The same judge runs in `delvec detail` over the entities a mark's `holder` writes, and the generators hold the same table through `invariants::assert_entities_are_holders`. |
| `DW0731` | `delvec prefab` | Audit: a hard-forbidden code-injection vector (command/structure block, NBT spawner, embedded `Command`). |
| `DW0732` | `delvec prefab` | Input error (unreadable `.nbt`/metadata/JSON). |
| `DW0733` | `delvec prefab` | Audit: a palette block state does not exist in Minecraft 1.21.11, **in a template whose `DataVersion` is the pin (4671) or later** — no datafix runs on such a file, so the game loads the block as air (error). The game datafixes every structure it loads against the file's own `DataVersion`, so invalidity-at-pin alone is not the rule; the pre-pin case is `DW0734`. Rule lives in `delvec::schem::blocks::BlockRegistry::judge_at`. |
| `DW0739` | `delvec prefab` | **A whole-piece command was handed ONE TILE of a tiled zone** (exit 2). A zone past the 48-per-axis cap ships as several `.nbt` plus one manifest; every command that takes a single `.nbt` will otherwise answer confidently about a fragment — `audit` returns `pass` over a fifth of a zone, `lighting` measures a fifth of a building, `socket` edits one tile of a set, `gallery` puts slices of one building on separate plinths. A tile is recognised by the name `<base>.x<i>y<j>z<k>.nbt` that `split::part_filename` gave it, which is carried by the bytes through any copy or move; the manifest beside it only enriches the message. Pass the manifest instead — **and every door that prints this sentence takes one**: `audit` and `lighting` measure the reassembled zone, and `gallery` shows it as one whole building placed from every template the manifest declares — a door that refused a tile and could not take the manifest it prescribes would be the pair defect `CLAUDE.md` names. `crates/delvec/tests/remedy_reachability.rs` takes the move at the door that printed it and asserts it reaches a whole zone rather than merely a zero exit. **Which commands owe this refusal is enumerated from the parser, not listed**: `crates/delvec/tests/prefab_fragment_doors.rs` walks `delvec::admit::cli::PrefabCommand`, requires every command it finds to be classified exactly once — piece door, or exempt with its reason — and separately requires that **no** command exits 0 when handed a tile, so an exemption cannot hide a door. A command added and classified nowhere is a red. |
| `DW0740` | `delvec prefab` | Catalog card schema/field validation failure. |
| `DW0750` | `delvec prefab` | Admission tooling (socket/anchor/lighting) failure. |
| `DW0752` | `delvec prefab` | **The lighting probe bound to ZERO cells** (exit 1): nothing was measured, so there is no profile to declare and `--write` writes nothing. The probe's binding is the floor a body can walk to from a ground-level entrance, and each filter can empty it for a different reason — no standable cell at all, no entrance on any vertical face (a piece whose way in is a jigsaw socket must be socketed before it is probed), or nothing reachable. The diagnostic says which. Zero binding is a **finding, not a pass** (CLAUDE.md): a measurement over nothing is not a measurement. There is no *nothing roofed* case: roofedness was a proxy for indoors that only a probe without a sky term needs, and it made every open-air piece — a courtyard, a jetty, a meadow — ungradeable. |
| `DW0753` | `delvec prefab` | **`lighting --write` has no prefab metadata to write the measurement into** (exit 2), and will not invent one. A manufactured skeleton — `source: unknown`, `spdx: UNKNOWN`, no `generated_by` row and `anchors: {}` — would be a document asserting that nothing is known about an asset, written silently and afterwards indistinguishable from a real admission record. A tool that cannot establish where something came from refuses. The measurement is still printed; create the metadata first, then re-run with `--write`. |
| `DW0760` | `delvec prefab` | Gallery emission / curation failure. |
| `DW0782` | `delvec prefab audit` | **A piece's declared spatial contract disagrees with its own blocks** (spec-0036 §2) — the second of the contract checker's two doors; the first is `delvec grammar expand`, which writes no `.nbt` when a gate is red. Each failed obligation is reported as one error line naming the gate, **its binding count** and what it found; each opt-out instance (an open envelope, a sightline, an out-of-walk region with its computed kind, a declared way with its sign and cell count, a way or bar the walk had to open, an exterior face) is reported as one advisory line, always, because a list is what a reviewer reads and a count is what a blind script satisfies. One enumeration, both doors: this is the same list `delvec grammar expand` prints, because it is the same checker. Raised for a piece that declares a contract, whichever way it is packaged: a single structure template, and a **tile-set manifest**, whose contract and anchors are zone-relative and are therefore judged against the assembled zone rather than against any tile — including a **contingent edge whose cells straddle a tiling seam**, which is judged over the reassembled zone and over no tile alone. A piece that declares no contract is not judged here and says so as `DW0783`. Exit 1. |
| `DW0783` | `delvec prefab audit` | **The second door did not judge this piece**, with the count of what it therefore did not examine. One rule at two severities. A **warning** where the door was entitled to stay shut: the declaration document carries no `spatial_contract`, or there is no document beside the bytes yet (an ingested piece is audited before its metadata exists). An **error** (exit 1) where the door COULD NOT judge: the document does not parse — a piece whose contract nobody can read is not a piece without one — or it declares no contract while its own anchors carry the `resolves_to` an exporter writes only out of a contract, which means the declaration was dropped from the document rather than never made. That last is what keeps the "declares none" case from being an opt-out the defect can supply: a step that loses a top-level key on write leaves behind the anchors it modelled, and the corroboration states its own binding count, so a document with no anchors is visibly one that nothing here could have contradicted. Split from `DW0782` because "the contract and the blocks disagree" is a fact about a piece that HAS a contract, and a piece nothing was asked about is a different rule — sharing one code leaves the silence reading as the pass. Every outcome, including the two warnings, is also recorded in the machine-readable report as `contract.state` plus the door's binding counts (files, cells, declared spaces/regions/edges/anchors, obligations run, objects examined, anchors carrying a resolved element), so a report whose door never opened is not the same artifact as a report whose door opened and found nothing wrong. |

`delvec render` exit codes: `0` ok · `2` input · `3` output · `4` fidelity-gate
failure · `5` renderer/GPU · `10` internal.

#### A dark shot's frame (night vision)

A shot stamped `{"profile": "dark", "mitigation": "night-vision"}` is drawn by
`delvec frames` under the light its written world carries, without the
night-vision effect, and its index entry and manifest name the lightmap under
`unchecked` ("judge in game under night vision"): the pinned renderer draws no
night-vision lightmap yet (spec-0112 phase 2). Its geometry is judged in a
frame lit by the room's own fixtures; its legibility under night vision is
judged in the game. Lit-stamped and unstamped shots carry no such line.
