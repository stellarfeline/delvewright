# `delvec::compiler::nav::learned`

The reference page for `crates/delvec/src/compiler/nav/learned.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../../compiler.md#5-diagnostics-catalog).

## Diagnostics

### DW1053/DW1054 — a shut way declares how it is learned (`compiler::nav::learned`; error; exit 3)

The rule is spec-0118. Judged at build, from the same call site as `DW1011` and over the same model: the configurations, a gate's faces, the party's reach and `can_be` are `compiler::nav::shutmodel`'s (`Configurations`, `faces_of`, `closure` through `party_reach`, `meet`), the functions `DW1011` ([`nav.md`](../nav.md)) reads, held together by an agreement test that drives both proofs over generated worlds and asserts they meet the same (gate, configuration, face) triples. **Population**: every gated connection (`Edge::shuts()`) whose seam gate `anchor/seam-<edge>` the world resolves — a connection declared `shortcut` **included** (unlike `DW1011`), because the wrong side of a one-way door is the face this rule is about. For each configuration the critical path passes through, each connection shut in it (every region cell solid), and each face the party's reach holds — on either side, the openable one or not — the triple is a **shut way met**. A face no body can be in on one side leaves the pair unstood, as `DW1011` counts it. **Junction and branch**: a breadth-first tree of body moves from the configuration's route cells (those a body can be in) reaches the face's nearest reached cell; the path's last route cell is the junction `J`, the cells after it the branch, whose length (moves) and rise (highest `y` on it minus `J`'s) are written and never judged. The **branch ground** is the ground only the branch leads to: the body-move closure from the face's reached cells, less the closure of the route cells with the junction and the branch path taken out, less the route cells — empty on an open floor, which is not a branch. **The three words**: `seen` — from the player's eye at `J` (`cell_center(J)` raised by `metrics::PLAYER_EYE_HEIGHT`, 1.62, the player's and not the 1.5 mob eye `World::has_line_of_sight` uses), `nav::walk_cells` to the centre of each region cell meets a cell of the region first among the cells `World::blocks_camera` holds (a bar is `solid`, so it is the blocking cell seen); `told` — `QuestsContent::answers_press_at(anchor/seam-<edge>)`, the predicate `DW0429` reads; `rewarded` — a reward anchor resolves to a point in the branch ground or a face-neighbour of it: a `collect`'s `anchor` (and the `holder` it adopts), an `interact`'s `anchor`, a `loot[]` entry's `anchor`, the `anchor` of the wave a `kill` names, an `ambush`'s `at`; a `reach-anchor` is not a reward. **Binding line**, printed before the verdict on every build that walks: `shut ways (DW1053/DW1054): G gated connection(s); over C configuration(s), M shut way(s) met at a face — D declared (S seen, T told, R rewarded), U undeclared, F declaration(s) not confirmed; I declared and never met shut`; ledger `validation/shut-ways.json` (`compiler::nav::ShutWayBinding`): the counts, `inert_ways`, and one row per shut way met — `connection`, `gating`, `configuration`, `face` (the node on that side), `openable`, `junction`, `branch_length`, `branch_rise`, `learned`, `confirmed`, and each word's finding (`seen`: `seen_from`/`bar_cell` or `blocked_at`; `told`: `answered_by` or `at`; `rewarded`: `rewarded_by` and its `kind`, or `ground_cells` and the `nearest` reward with its `distance`). A build that judges no gated connection writes it with every count `0`; a refused build writes no tree, so the red rows reach the reader through the message.

| Code | Meaning |
| --- | --- |
| `DW1053` | **A shut way the party meets, learned by no declared means.** A gated connection met shut at a face (above) whose `gating` names no `learned`. Raised once per connection, at the first configuration and face it is met, every failing connection named (six, then a count). The message names the connection with its class and gating, the configuration (`while \`obj/…\` is next`), the face by the node on that side and whether it is the side the way opens from, `J`, the branch's length and rise, and what each word would need there: `seen` — the bar is seen from `J`, or hidden behind the named cells; `told` — the trigger that answers a press at `anchor/seam-<edge>`, or that nothing does; `rewarded` — the reward on the branch, or none within the branch's `N` cell(s) and the nearest. Repair: write the word that is true, or make one true and write it. The gallery's probe `a-shut-way-nobody-is-told-of` (the site-plan point with `learned` removed from `edge/east-door`, the one-way door met from its wrong side) reds it. |
| `DW1054` | **A declaration the world does not confirm.** A shut way met whose connection declares `learned`, and the word does not hold there: `seen`, but from `J` the eye meets another cell before the bar (each blocking cell named); `told`, but nothing answers a press at `anchor/seam-<edge>` (the message carries the trigger JSON `DW0429` prescribes, `dsl::trigger::press_answer_prescription`, so the two rules name one remedy); `rewarded`, but no pickup, interaction or fight stands within the branch's `N` cell(s), the nearest reward anchor and its distance named. Repair, the world's or the word's: open the geometry so the bar is seen, write the trigger, place the reward, or change the word to the one that is true. **As a warning**, the same code names a `learned` on a connection never met shut in any judged configuration — counted into `I`, never refused: the judged configurations are the critical path's and the closure is branch-blind, so a way met shut only on a branch's own path is not in them, and refusing there would reject a legitimate design for an engine limitation (the rule `DW0891` states for a volume no modelled body reaches). The gallery's probe `a-way-said-told-that-nothing-answers` (`edge/west-door` declared `told`, no `use` trigger at its seam) reds it. |
