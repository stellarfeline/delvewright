# `delvec::compiler::chain`

The reference page for `crates/delvec/src/compiler/chain.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../compiler.md#5-diagnostics-catalog).
What the module guards, and the world build it splits, are in [`compiler.md` §4](../../compiler.md#one-ticks-command-chain-stays-under-the-games-limit).

## The cost model

What the pinned game charges against one execution context's quota [cited — the three callers of `ExecutionContext.incrementCost` in the pinned 1.21.11 server jar]:

| Charged by | When | Counted as |
|------------|------|------------|
| `BuildContexts.execute` | once per `execute` sub-command stage that carries a redirect modifier, however many sources the stage forks into | every `execute` sub-command keyword before `run`, as the pinned command tree names them, once per line — an upper bound, since a keyword can also be an argument's literal (`positioned as`) |
| `ExecuteCommand.execute` | once per executing source, for the command a chain ends in | one per source the line's forks leave |
| `CallFunction.execute` | once per executing source, for a function call | per source the line's forks leave: one for the call, then the callee's body |

The limit is the default of `max_command_sequence_length` [cited — `GameRules.MAX_COMMAND_SEQUENCE_LENGTH`, `ldc 65536`, in the pinned server jar]. A function's **chain** is one for its call plus every line's cost; a line costs its stages once, and its final command — or, for a call, the callee's chain — once per source its forks leave; `schedule function` runs nothing this tick and costs its own line.

**Forks, at a full party.** Every chain is measured at the largest party a delve is made for (`delvewright_dsl::wave::MAX_PARTY`, 4), so the quota declared holds for every party of one to four. The stages that fork are `as`, `at`, `positioned as`, `rotated as` and `facing entity` over their entity argument, and `on passengers`; every other stage keeps one source per source. An entity argument forks into: `@s`, a name or a UUID, one; `@a`, or `@e` with a player `type`, the party, or its `limit` when that is less; `@p` and `@r`, their `limit` (default one), at most the party; `@n`, its `limit` (default one); any other `@e`, its stated `limit`. A fork whose selector states no bound — `@e` with no `limit` and no player `type`, `on passengers`, a macro argument — is held to the game's **fork limit**: a stage never leaves 65536 sources or more (below). Forks multiply, and the product is held to the same limit after every stage: `execute as @a at @a` is sixteen sources at a full party. The binding states the longest chain at the full party and at one player, and how many lines only the fork limit bounds; the ledger names none of them individually but counts them (`at_the_fork_limit`).

**The fork limit** [cited — the read site below]: `BuildContexts.execute` reads `ExecutionContext.forkLimit` once, then for each stage with a redirect modifier charges one unit (`incrementCost`) and, for each source, gathers what the modifier answers; when the sources gathered so far plus that answer reach the limit it raises `command.forkLimit` and stops the line. `forkLimit` is the `max_command_forks` gamerule (default 65536) read when the context is made, as the sequence length is. So no stage leaves more than 65535 sources.

## Where the quota comes from

How the pinned server sizes a context's quota [cited — the read site below]:

- **One context per root.** `ServerFunctionManager.tick` runs each function of `#minecraft:load` (on the first tick after a reload) and then each function of `#minecraft:tick`, one `ServerFunctionManager.execute` per function, in the tag's order; a scheduled function (`FunctionCallback`, `FunctionTagCallback`) goes through the same `execute`. `execute` hands the call to `Commands.executeCommandInContext`, which makes a new `ExecutionContext` when the thread holds none, runs it and closes it: every root, and every command a player, rcon or a reward runs, gets its own.
- **The quota is read when the context is made.** `executeCommandInContext` reads the level's `GameRules.MAX_COMMAND_SEQUENCE_LENGTH` (`max(1, value)`) and `MAX_COMMAND_FORKS`, and passes them to `new ExecutionContext(commandLimit, forkLimit, profiler)`; `commandLimit` is final, so a `gamerule` line changes the quota of every context made after it and never the one running it.
- **The rule.** `max_command_sequence_length` is an integer rule, default 65536, minimum 0; `max_command_forks` beside it has the same default.

**The quota a build declares.** Every tick repeats work that grows with the campaign and cannot move to a later tick. `chain::declare` runs after the tree's last writer: it measures every function any datapack of the tree ships (the delve's own, the creator overlay, the PackTest pack, which run beside it under its quota) that no `#minecraft:load` entry runs, and when the longest exceeds the default it writes `gamerule max_command_sequence_length <that chain>` as the first line of the first function the delve's `#minecraft:load` tag names (`<ns>:load`). The value is the measured chain itself, a function of the shipped bytes. The `load` context that runs the line was made before it, so a `load` entry and everything it calls (`setup` included) keeps the default; every context made after it — each tick entry, each scheduled step, each reward, each command — has the declared quota, and the world saves the rule. A build whose sources fit the default declares nothing and is byte-identical. The quota is a cost the build states and the host meets (CLAUDE.md, *Host hardware never caps a capability*): it is printed in the binding line and written to the ledger.

A function that reaches itself in the same tick has no chain unless it is a **counted loop**: it calls itself only under `if score <h> <o> matches ..<n>`, adds one to that score unconditionally before the call and writes it nowhere else, and every line that enters it from outside last wrote the score with an unconditional `scoreboard players set <h> <o> <k>`. It then runs at most `n - k + 1` passes per entry, and its chain is that many passes. The creator overlay's aim ray is one (256 passes).

## Diagnostics

### DW0984 — one tick's command chain stays under the game's limit (`compiler::chain`; error; exit 3)

| Code | Meaning |
|------|---------|
| `DW0984` | **A shipped function's command chain could pass the game's limit.** Build tier (exit 3), `compiler::chain::check`, an **engine self-check** read off the finished tree after emission, over every function of every datapack the tree ships (the delve's own, the creator overlay, the PackTest pack) against one name space. A function whose chain — its own commands and every function it calls in the same tick, costed as above — exceeds the quota of the context it runs in, or that reaches a call cycle that is not a counted loop, is refused; every chain is measured at a full party (see *Forks, at a full party*): the server would stop it part-way with `Command execution stopped due to limit` and nothing would read the line. The quota is read back off the shipped bytes: the last unconditional `gamerule max_command_sequence_length <n>` line of a function the delve's own `#minecraft:load` tag names is the declared quota (a line anywhere else declares nothing); a `#minecraft:load` entry of any datapack, and everything it calls, is held to the default (or a lower declaration), and every other function to the declared quota, the default when nothing is declared. Since a caller's chain holds its callee's, refusing every function refuses every root. It still refuses what a declaration cannot bound: a cycle, a `load` past the default, a source past what the build declared, a need past the gamerule's `int`. The message names how many functions refuse, the first, and the quota it was held to; the remedy is the emitter's — one-shot work splits across ticks (`chain::steps`, `schedule function`), as the world build does, and a source outside `load` is covered by the quota the build declares (`chain::declare`). Nothing in the campaign repairs it. **Binding.** Every build prints `chain binding: F shipped function(s) measured, L counted loop(s), S world-build step(s); longest chain N (`f`) at a party of 4 (M (`g`) at one player), against <the declared limit, or the game's default limit of 65536>, and K function(s) a `load` runs against 65536; L line(s) fork over entities only the game's fork limit of 65536 bounds; R refused (DW0984).` and writes `validation/chain-length.json`. |
