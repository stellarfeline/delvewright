# `delvec::compiler::attached`

The reference page for `crates/delvec/src/compiler/attached.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../compiler.md#5-diagnostics-catalog).

## Every block the build writes is one the server keeps

A block whose pinned `canSurvive` rule asks a neighbour for something — a wall torch, a lever or a ladder a full face behind it, a torch or a lantern a face sturdy at its centre, a flower its soil, a carpet anything but air, a door's upper half its lower half — is removed by the server the first time a shape update reaches it when no neighbour gives it. The rule is the jar's, measured: `delvewright_dsl::support` reads `crates/dsl/data/support-1.21.11.tsv` and `support-bases-1.21.11.tsv`, written by `tools/maintenance/dump-support.py`, which asks the pinned server's own `canSurvive` over a level holding the block and one neighbour, for every neighbour cell and every blockstate of the registry.

**Three arms judge it, and each prints its binding on every build that reaches it.**

- **The load world** — the one `DW0955` compares (`view::beat::load_blocks` over `view::beat::picture_base`: pieces, world edits, world-load seals, relight fixtures, trigger props, in the critical path's configuration at its first step): every block that needs support. A cell nothing was written to is air, except under the `ocean` horizon, where the generator's water (`floor_top < y ≤ level`), stone and bedrock stand outside every placed piece's box. Binding: `attached blocks (DW1002): A of N non-air cell(s) at load need a neighbour to stay — H held, D dropped; unjudged by the measured rule: U cell(s) (block xn, …); not in the table: K cell(s) (…)`.
- **The write sequence** — the load as the server runs it, read off the shipped functions in run order (`setup`, the ground steps `ground_verify` starts, `place_all`, the world-build steps `place_verify` starts, `setup_finish`), every `place template`, `fill` and `setblock` laid in turn. Who is asked `canSurvive` as a write lands is the pinned jar's (read from its bytes with the official mappings): `/place template` asks every block it placed (`StructureTemplate.placeInWorld` → `updateFromNeighbourShapes`, and the template's own unheld block is set to air silently) and every neighbour its writes reach; `/fill` and `/setblock` keep the block they place even where it cannot survive (`BlockInput.place` falls back to the state as written) and ask each neighbour whose rule reads a cell they changed, which the server drops as an item when it fails. A falling block (`assembled::is_falling_block`) written in a function, or standing over a cell it changes, is asked of the cell below once that function has run — the pinned `FallingBlock.isFree`, measured into `support-bases-1.21.11.tsv`'s `f` flag; one that falls is refused, because a write that lands under a falling block turns it into an item on the ground. A conditional write is counted and not laid; a block-writing line the reader cannot lay (a `clone`, a tag filter, a template no piece places) refuses the build by name. Binding: `write sequence (DW1002): W write(s) the load runs in order over F function(s) — T template(s), L fill(s), S setblock(s); C changed cell(s) …, A attached and G falling block(s) among them, D not kept; K conditional write(s) not laid; U line(s) not read`.
- **The runtime writes** — every block-writing line of every shipped function the load does not run, conditional or not (a `set-block`, a `fill-region` or `clear-region`, a gate, a way, a collapse, a prop, on any path, branch or beat nobody has to play), laid at once over the loaded world: a cell may hold its loaded block or any block any write leaves there, a `replace` filter admitting its write only where the cell may hold the filter's block, and a block beside a write that also wrote this cell standing on what that write left. The upper half of a two-high block (`half=upper`, [`region_fill`](../../compiler.md)) is never judged against what a write leaves in its lower half's cell when that one write also writes the upper half's cell over it: the write takes the block whole, and the pinned jar's loot tables give an upper half no item of its own once its lower half is gone. Any other block is still judged so: a torch whose floor one `fill` clears with it is shape-updated as its floor goes, and drops. Every cell reached and its six neighbours are judged against all of it, as the jar asks: an attached block whose rule reads a cell some other write changes must be held by every state that cell may hold (a block no write's change reaches is never asked again, so an effect's block hung on air floats rather than drops); a falling block an effect places, or one standing over a cell a write changes, must have no state below it that it falls into. Every configuration a path, a branch or an unforced beat can reach, in any order, is one of these, so the arm can only refuse more. A line with a relative position is counted and named on the binding, never laid. Binding: `runtime writes (DW1002): R block-writing line(s) outside the load, in F function(s), K of them behind a condition, may change C cell(s); J cell(s) judged … (P block(s) judged) …; D not kept; U line(s) not read`.

The arms run after the route proofs and the function emission, so a climbable a forced leg needs is named by `DW0991` first; one refusal names every block any arm finds.

**What it cannot judge** is counted, never refused: a block whose table row is `unjudged` (a crop asks the light, a vine or glow lichen reads a cell beyond its six neighbours, a big dripleaf stem needs two neighbours at once) is listed by block on the load binding, and so is a block the table does not hold.

**A superset of what the server shows.** The server drops an unheld block only when an update reaches it; a block nothing ever updates stays, held by nothing, until a gate, an edit or a runtime write next to it moves. `DW1002` refuses the block the rule does not hold, and `DW0955` sees a dropped block as a differing cell, and one that fell as an item entity in the save it compares.

**The same rule everywhere a block is chosen.** The relight pass sites a fixture only where the measured rule holds it, reading every cell the campaign rewrites after load as air (`light::fixture_keep_out`), and `DW0354` judges an edit's placed blocks by the same table. Nothing in the engine states a support rule by hand.

## Diagnostics

### DW1002 — a block the server drops (`compiler::attached`; error; exit 3)

| Code | Meaning |
|------|---------|
| `DW1002` | **A block the build writes is one the pinned server drops.** Its measured `canSurvive` rule (`delvewright_dsl::support`) is met by none of its neighbours in the load world; or it is not kept as the load's own write lands (an attached block a template places, or a neighbour a write reaches, with no neighbour that holds it then; a falling block over a cell `FallingBlock.isFree` calls free once its function has run); or some configuration a runtime write can reach changes what holds it and leaves it held by nothing; or a block-writing line of the load cannot be read. Build-tier (exit 3), `compiler::attached`, after the route proofs and the function emission. The message names each block (up to eight, then the count, with a tally by block): its state, its cell, the write — function and line in the shipped datapack, and the command — or the piece whose box holds it, and for every neighbour that could hold it, that neighbour's cell, what it must give ("a full (sturdy) north face", "a down face sturdy at its centre", "be one of minecraft:dirt, …") and what stands there, or may. Prescription: repair it where the block is authored — give it what it needs in the same piece or edit that writes it, hang it on a block no write removes, or choose a block that needs nothing there (`references/when-red.md`). Gallery: `probes/a-lever-hung-on-a-pane` (load), `probes/gravel-left-over-air` (sequence), `probes/a-trap-that-takes-the-case-button-floor` (runtime, unforced), `probes/one-branch-takes-the-case-button-floor` (runtime, one branch). |
