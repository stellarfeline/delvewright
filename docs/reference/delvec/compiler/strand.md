# `delvec::compiler::strand`

The reference page for `crates/delvec/src/compiler/strand.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../compiler.md#5-diagnostics-catalog).

## Diagnostics

### DW0924 — a fight stays where the party can strike it (`compiler::strand`; error)

| Code | Meaning |
|------|---------|
| `DW0924` | **A body a `kill` objective waits on can get to a place it survives and the party cannot strike it from.** For every stack of a seated wave some `kill` objective names, the flood of the movement a mob has (`World::mob_moves`, the relation `DW0922` floods: walking, a step or jump up one block, a perch on a barrier top, a drop off any edge to the first floor it survives, floating in water) from the seats the seating pass chose, within the stack's follow range (the radius `DW0478` reads: a lane's `aggro_radius`, else the declared `follow_range`, else `nav::DEFAULT_FOLLOW_RANGE`); a drop from inside the range lands wherever it lands, because pursuit bounds a walk and gravity bounds a fall, and a body a blow knocks off an edge lands exactly where one that walks off it does. A reached cell is **in reach** when a cell the party can be in holds an eye (`metrics::PLAYER_EYE_HEIGHT` over its feet) within `strand::STRIKE_REACH` (3.0 blocks, vanilla's default `entity_interaction_range`) of the body's box there, the box taken from the cell floor to a block over its height and no line of sight demanded, so the rule leans toward reach. The party's cells are where it can **walk** (`World::reachable_walkable`, the walk graph every route is proven on — a drop the party might survive is no route to a fight) from everywhere the party **certainly stands** on the forced route — the entry spawn, every checkpoint seat, every crossing's entry point and every link's `to` (`lethal::stands_at_roots`, spec-0083 §3.8), and not a gather's destination, which an optional root may never fire, over the world with its gates as the base world holds them and furniture lifted, less every cell outside the playable region (`boundary`), whence the clock carries a body back. A stack is **stranded** when a cell it reaches has no mob movement back to a cell in reach. Only the hand is counted: a bow reaches further, and whether a class carries one is a question about the fight. Build-tier (exit 3), asked right after `DW0921`, whose party pocket is the worse finding. The message names the wave, the body, the objective, the seat, the cell, the falls on the way and how many cells are stranded. Prescription: close the edge (a parapet a body is knocked into and not over), give the party a way to where it lands, or seat the wave where nothing it can fall to is out of reach — never mark the shelf unwalkable, never shrink `follow_range`. **Binding**: `DW0924 binding: N kill-objective wave(s), N stack(s) over N seat(s); N cell(s) a member can reach within its follow range, N of them within a strike of the N cell(s) the party can be in; N stack(s) can be stranded out of reach`, printed on every build that seats a wave a `kill` objective names, and `validation/strand.json` (the same counts, `examined` = stacks) when it holds. |
