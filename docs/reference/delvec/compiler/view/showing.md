## Diagnostics

### DW07xx — asset, render and authoring tooling (spec-0007; `delvec` subcommands)

This module's rows of a section whose prose is on the [`delvec::admit::diag` page](../../admit/diag.md#dw07xx--asset-render-and-authoring-tooling-spec-0007-delvec-subcommands).

| Code | Tool | Meaning |
|------|------|---------|
| `DW0894` | `delvec viewer` / `delvec render piece` / `delvec render batch` | **A piece nobody has measured the light of is not shown to anybody** (error, exit 2; `compiler::view::showing`). A prefab reaches a person's eye through exactly three arms. The grammar exports `"profile": "unmeasured"`, which is the true statement it can make — it places blocks, not photons — and the only two things in this engine that measure light are a command somebody has to type (`delvec prefab lighting`, `DW0751`) and the compiler's assembled-world survey, which quantifies over the **areas of a campaign** (`DW0210`). A piece that enters no campaign meets neither. It is asked **at the showing** because a picture is the one medium darkness does not show in: the renderer lights every frame for the camera and not for the body. **Its remedy is not a hand step, and that is what makes it shippable.** A hand remedy (`delvec prefab lighting --write`) would not survive: an export rewrites the whole metadata document, so the next `delvec grammar expand` resets the field the command wrote — two actions each undoing the other, one prescribing what the other refuses. So `grammar::export::measured_lighting` takes the measurement where the bytes are produced, and this code keeps only the check. Preserving the written field instead was rejected: `shown_faces` takes that shape correctly because it is a **declaration**, part of what the building is, while a lighting profile is a **measurement of the bytes**, and carrying one onto bytes it was not taken over makes the document's own `method` line (`min over N floor cell(s) …`) false about the piece it sits beside. **The one thing it does not refuse, and the reason that is not a hatch**: a piece with nowhere in it to stand has no floor to be dark, so `unmeasured` is the true answer there. The escape is the standable-cell COUNT taken from the bytes at the moment of showing — never a field, a flag or a word in the document — and the defect this code exists to catch is a dark ROOM, which has floor by definition. Measured over the rule library: 30 of its 36 programs export a measurement (16 `dark`, 14 `lit`) and 5 report `standable_cells: 0`, every one of them a demonstration of an IR construct rather than a building. A sealed crypt is deliberately not in it — it has floor, so it is refused until somebody measures it, which is `DW0752`'s "socket it first, then probe it". **Three shapes, one rule — nobody measured this** — and each names its own remedy: the document declares `unmeasured`; the document declares no `lighting` block; there is no document beside the bytes at all. **A measured `dark` profile is shown**: the rule is that somebody measured it, and whether `dark` should itself refuse is `DW0751`'s question, which this code does not decide. **Bound at every door, and ahead of the renderer at each**: `compiler::view::cli::run_viewer`, and `render::cli::judge_before_showing` from both `run_piece` and `run_batch` — each **before its own `resolve_textures`**, so a creator with no client jar is told *this piece was never measured* rather than *I could not find your textures*, which is true and useless. A gate bound at one of the doors a piece reaches an eye through is bound at none, and one bound behind the GPU init costs the refusal its whole value: after the pack it costs a device, after the frames a directory of PNGs the reviewer must be told to ignore. `the_render_arms_refuse_an_unmeasured_piece_before_they_resolve_textures` pins the order at both GPU arms with every texture fallback (`--textures`, `$DELVEWRIGHT_CLIENT_JAR`, `$HOME/.chunky`) pointed at one absent path, so the exit code is decided by the ordering alone and not by whether the machine happens to have a jar; moving the call behind `resolve_textures` turns exit 2 into exit 5 and reds it. `batch` judges every piece it resolved before loading the pack, so a library with one unmeasured piece in it fails whole instead of after twelve prefabs have rendered. **Binding**: `light measurement: N of M piece(s) about to be shown carry a measured lighting profile (K carr(y/ies) none and have nowhere in them to stand, so there is no floor to measure)` on every run, zeroes included. |
| `DW0895` | `delvec viewer` / `delvec render piece` / `delvec render batch` | **Floor under a roof that no body can walk to, and the step the walk was turned back at** (warning; `compiler::view::showing`). A roofed room with no way into it renders exactly like one with a door, and reads as finished. The engine holds both halves of the answer — the standable set and the walk that floods it from the piece's grade entrances — and this subtracts one from the other. It is a **report and never a refusal**: the engine cannot tell *unreachable* from *not meant to be reached* — a parapet is standable and nobody walks it, a sealed crypt is floor on purpose — and a gate that cannot draw that distinction is one an author learns to route around. Cells open to the sky are counted and never raised, for the same reason. What it can do is say **how much, where, and which step**: the roofed stranded count, the pockets it forms, the box of the most roofed one, and the frontier — every step the walk was refused at the edge of what it reached, classified by the step rule's own two ways of saying no (`metrics::step_allowed`). **The headroom arm is the one that is invisible at every scale below the whole building**: a standing body owns the cell it is in and the one above it, so a full-block rise is a jump and the cell two courses over the **takeoff** must be clear. A stairwell opening cut one course short therefore strands every storey above it while the flight itself walks, every render shows a floor at the top of it, and the same flight alone in an open box tests fully reachable. The message names the course to open, by cell. **Binding**: `enclosure: <id> — N of M standable cell(s) reachable … R refused step(s) at the edge of the walk, H of them one course of headroom short` on every run, zeroes included. |
