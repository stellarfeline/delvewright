# `delvec::compiler::telling`

The reference page for `crates/delvec/src/compiler/telling.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../compiler.md#5-diagnostics-catalog).

## Diagnostics

### DW0981/DW0982 — what the dialogue tells the player (`compiler::telling`; error; exit 1)

Two rules of `docs/reference/game-writing.md` made mechanical, both judged at `delvec validate`, where the line is written. Neither reaches the datapack. Every string is read as the player reads it: a styled span (spec-0096) is its own text (`dsl::textstyle::visible`), so a question inside markup ends in its own `?`, and a name, a use or a gloss in markup is matched by the words it draws.

**A question gets an answer (`DW0981`).** An option whose `label` or `tooltip` — in English or in any declared-language sidecar rendition — ends in `?` or `？` is the player asking. Choosing an option with no `next` closes the dialog, so the player asks and the conversation ends. The option must lead to a node of the same tree that has a line, and not back to the node it stands in. Whether the line answers the question is the writer's; that a line follows is the engine's. The quantifier is every option of every tree.

**A name is told before it is used (`DW0982`).** The names are the l10n inventory's `name` and item-name rows (`dsl::key_kind`), the declared set the transcreation fact check holds to one rendering: a person, a body or wave, a place, a counter, an item. A *use* is an occurrence in an NPC's line or an option's label or tooltip, written with the name's capitalisation or as a definite reference (`the`, `my`, `this`, … before it), so `keep watch` is a word and `the watch` is the name; a name inside a longer declared name is held to the longer one. A name is *told* by the person it belongs to speaking to the player (their dialog is titled with it), by the class picked and its kit, by an item handed over, or by a sentence that says what it is — after `a`/`an`, after `called`/`named`/`known as` or `this is`/`here is`/`I am`/`we are`, followed by an apposition (`, the…`, `— a…`), by a full stop and an indefinite (`Vesperhold. A king, a court…`), or by `is`/`are`/`was`/`were` and an article; a possessed or pointed-at thing (`your tallow is…`) is not glossed. A nameplate, a counter, a bar's title and an area's name show a name without telling it, and a definite mention presupposes it.

Every string is placed at the first state of the replay's own walk (`flow::Walk`) at which the player can read it, on the exported critical path and on every realised branch's path: a dialogue line or option where `Walk::dialogue_on_screen` draws it (the live cast scene, nodes reachable through drawn options, an option drawn when its flags hold and every objective it completes is pending under its whole guard — quest running, every `after` done, the objective's flags holding, not yet done; a numeric term read as open — the model of `emit::dialogue::option_display_conditions` and `emit::quest::pending_guard`), and, at the state a `talk-to` step leaves, whatever the `next` node of the option that took it draws (`Walk::dialogue_on_screen_after`), since the click shows that node at once; an objective's title and hint once its quest runs and its `after` is done; a quest's goal and barks once it runs; an effect's strings at the step that fires them (`dsl::effect_string_sites` pairs each pointer the replay records with its key base). A string the walk cannot date — an environment trigger, a refusal, a reaction bundle, loot, a stake message — is placed at the start, so it can tell a name early and never makes a use look early. Each refusal names the first walk state the use is on screen, the walk, and the labels and mentions the player had seen; one refusal per string and name, at its earliest state over all walks.

`delvec validate` prints the binding: `name-told binding (DW0982): <names> declared name(s); <walks> walk(s); <read> of <declared> dialogue string(s) on screen on some walk; <uses> use(s) of a name in them, <untold> untold`. Not checked: Chinese renditions (the English is the key of record, and one name, one rendering is the fact check's), and a place or thing the documents never name — an anchor's id is not a name the player is given, so `my stand` for an anchor the story never introduced is the writer's to catch.

| Code | Meaning |
|------|---------|
| `DW0981` | **A dialogue option asks a question and nothing answers it.** Its `label` or `tooltip` (English or a sidecar rendition) ends in `?` / `？`, and it has no `next`, a `next` back to its own node, or a `next` whose node has no line. Path `/content/dialogues/<t>/nodes/<n>/options/<o>`; the message names every rendition that asks. Prescription: give the option a `next` node in which the speaker answers plainly, in their own voice; a `complete-objective` still fires when the option is chosen, whatever node it opens. If the player is not asking, word the label as what they say. Validation tier (exit 1). |
| `DW0982` | **A declared name reaches an NPC's line or an option before the play order has told the player what it is** (game-writing.md §3 N1/N3). Path the string's own (`…/text`, `…/options/<o>/label`, `…/tooltip`); the message names the name and the row that declares it, the walk state and walk, and up to three labels or mentions the player had already seen. Prescription: tell it first, in a line the player reads before this one (the name with what it is, `called …`, or an indefinite that brings it in), or have the speaker say it in words the player already has. Validation tier (exit 1). |

### DW0983 — a name tag marks a person (`compiler::telling`; error; exit 1)

A custom name over a body (`waves[].mobs[].name`, `actors[].name`, emitted as `CustomName` with `CustomNameVisible:1b`) says the body is someone. `game-writing.md` §3 N6: a crowd of ordinary bodies wears none. The object decides which bodies are unique — no flag opts out. Names are compared as drawn, so `Footman` and `[[bold|Footman]]` are one name. A skin does not change the rule: two actors may wear one skin file (spec-0097), and each still stands or falls by its own name. A name is a **group's** when one wave spawns more than one body under it: an entry with `count` > 1, or two entries of one wave carrying it. A group's name names no one, so every wave entry and every actor carrying it is refused, in every wave. A name borne by one body in each encounter it appears in stands: a boss or elite as a `count: 1` entry inside a wave, a named actor, one character as a wave member and later as an actor. The quantifier is every `waves[].mobs[]` entry and every `actors[]` row. Judged at `delvec validate`, which prints `name-tag binding (DW0983): <named> of <waves> wave(s) carry a named member, <n> named actor(s); <g> name(s) tag a group; <w> wave(s) and <a> actor(s) refused`.

| Code | Meaning |
|------|---------|
| `DW0983` | **A name tag on one of many.** A wave entry or actor carries a name that a wave spawns more than one body under. Path `/content/waves/<w>/mobs/<m>/name` or `/content/actors/<a>/name`; the message names the wave that makes it a group. Prescription: remove `name` from the entry (a fight that needs a heading states `health_bar.title`); a body that is a character gets its own `count: 1` entry and its own name. Validation tier (exit 1). |
