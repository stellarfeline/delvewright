# `delvec::compiler::cohabit`

The reference page for `crates/delvec/src/compiler/cohabit.rs`: the diagnostics-catalog row of every DW code
this module declares. The catalog's shared rules are in [`compiler.md` §5](../../compiler.md#5-diagnostics-catalog).

## Diagnostics

### DW0896 — one mark, one body (`compiler::cohabit`; error)

A mark is a cell, and a cell holds one body. This proves no two bodies whose
lifetimes overlap are declared on the same one — the body-against-**body**
counterpart to `DW0450` (body against block) and `DW0359` (body against
affordance).

| Code | Meaning |
|------|---------|
| `DW0896` | **Two bodies that are in the world at the same time are declared on one cell.** Build-tier (exit 3), `compiler::cohabit`. A castle-tour campaign's closing muster declared a captain of the guard and six men-at-arms, all seven on `anchor/stop-gate`; the build exited 0 and the datapack carried `summon minecraft:mannequin 77.5 68.0 40.5` seven times — one coordinate triple for seven bodies. On the ground the only thing separating them was that each `move-actor` walked off the mark at a slightly different speed, so the rank the author wrote came out as single file. **The rule is co-existence, not a shared anchor**, and that distinction is the whole of it: `actor/sergeant` and `npc/marshal` share the mark `anchor/muster + [1, 0, 0]` in the engine's own gallery, deliberately, because the engine supports a **handoff** — one body leaves a mark and another takes it. A rule keyed to a shared anchor would refuse that or be widened until it bound to nothing. **It is a claim about the declaration, never about a tick.** It does not ask whether two bodies are inside each other at some instant: a body that has walked off its mark is not on it, and answering *that* would make the verdict depend on `move-actor` speeds, which is exactly what the muster was relying on. It asks whether the campaign gives two simultaneously-living bodies one cell to be summoned onto. **Two arms, and the compiler states only what the structure proves** (`compiler::timeline`'s stance, and its replay — one ordering rule, one implementation, shared with `DW0410`). **(1) World init**: every non-`deferred` npc stands on its mark from tick 0, unconditionally and at once, so two of them on one cell are in one cell before any effect fires; no timeline is consulted and no permanence is required. **(2) A body still standing when another is summoned**: a body is *provably live* at an entry when nothing in the campaign can remove it AND it is either a world-init body or was entered by an **unconditional** `spawn-npc`/`spawn-actor` earlier in that entry's **own** timeline. Cross-bundle order is unknowable and is never guessed. *Nothing can remove it* is `QuestEffect::body_exit` over every effect at every depth — `despawn-npc`, `despawn-actor`, and `unleash-actor`, after which the body is a real-AI twin the compiler makes no claim about — plus, for an actor, `vulnerable: true`, since a body a player can kill has a lifetime the compiler cannot bound. The live set therefore holds only bodies whose liveness cannot be revoked, and the replay models no exit at all. **The asymmetry is conservative in both halves**: a conditional entry never proves a body is standing (it may not fire), while an entry is *judged* whatever its own condition is (it collides on every run where it does fire). **Both entry points are enumerated** — a quest bundle's `spawn-npc`/`spawn-actor` through `plan::for_each_effect_root`, and a dialogue option's `spawn-npc` through `DialogueEffect::body_entry`, whose live set is the world-init one because a dialogue option is not a root the timeline replay orders. Bodies are walked once, through `dsl::body_sites`, and resolved once, through `Plan::body_point` (area-scoped for an npc, across every placed piece for an actor) — the same walk and the same resolution `DW0450` reads, so a third body class enters this proof by existing. A body whose anchor does not resolve is skipped; `DW0325`/`DW0345`/`DW0360` own dangling references. **No escape hatch, and none is possible.** Two entity bodies at one coordinate interpenetrate — a puppet is `NoAI`/`immovable` and does not even push its neighbour away — and the DSL expresses no mount, no rider and no stacked body, so nothing an author can write wants this. An opt-out could only be secured by the author's say-so, which is the property a mistake also supplies. **What it deliberately does not catch**, each a withholding rather than a gap in the model: bodies one cell apart whose hitboxes still meet (the rule is the cell — a box rule needs a margin, and `DW0450` is the box rule); a pair *both* of whose bodies carry an exit (the muster's six men-at-arms each end in a `despawn-actor` inside their own `move-actor`'s `on_arrive`, which is not ordered against the enclosing bundle's later siblings, so the captain is caught against every one of them and they are not caught against each other); and a pair whose entries sit in two different bundles. All refused pairs are named in one message, normalised so one pair is one finding. Prescription: give each body its own mark — an offset apiece from one anchor, so a rank of bodies is one anchor and a cell apiece (spec-0066) — or make the campaign prove they take turns by removing the first before the second is summoned. `remedy_reachability.rs` takes the offset move: seven live bodies on one anchor, then the same seven at `[-3..3, 0, 0]`, green under `DW0896` and `DW0897` both. **Binding**: `one-mark binding: N body(ies) declared, M of them resolving to C distinct cell(s); I stand there from world init and P are bodies nothing in this campaign can remove; Q co-existence question(s) asked over E entry event(s), R refused (DW0896)` on every build, zeroes included — a count only says something when the run that found nothing prints it too. |
