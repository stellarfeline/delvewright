# i18n — translating a campaign's l10n sidecar

Live reference for how a delve gets its non-English strings. Companion to the
compiler reference's [l10n sidecars](compiler.md#l10n-sidecars-l10ncodejson)
section, which owns the key scheme and coverage rules.

**Generation-time only.** A shipped delve never calls an LLM (CLAUDE.md forbidden
zones): translation happens while the campaign is authored, the result is written
into the campaign source as `l10n/<code>.json`, and `delvec build --lang <code>`
bakes those strings into the datapack. The running server talks to nothing.

## Who translates

Two interchangeable producers of the same artifact:

| producer | when |
|---|---|
| the `/new-delve` agent, in-agent | default — no config, no key, no network |
| an external OpenAI-compatible LLM API (`tools/i18n-translate.py`) | when `[i18n]` is configured **and** the key env var is set |

The sidecar committed to the campaign repo is the **artifact of record regardless
of who produced it**. Nothing downstream — compiler, validation, release — can
tell, or cares. A hand-edit after the fact is just as legitimate as a generated
line.

## Config

`delvewright.toml` at the engine repo root is the committed, inert convention
file; put real settings in `delvewright.local.toml` (gitignored, same shape,
overrides key by key). Neither is a build input — the compiler never reads them,
so nothing here can move a delve's bytes (ADR-0006).

```toml
[i18n]
provider = "openai-compatible"                # only supported value
base_url = "https://api.deepseek.com/v1"
model = "deepseek-chat"
api_key_env = "DELVEWRIGHT_I18N_API_KEY"      # the NAME of an env var, never a key
temperature = 0.2                             # optional (default 0.2)
batch_size = 40                               # optional keys per request (default 40)
timeout_seconds = 120                         # optional (default 120)
max_retries = 3                               # optional (default 3)
reflect = false                               # optional three-step pass (default false)
```

**The key never enters a file.** `api_key_env` names an environment variable; the
tool reads it at call time, sends it in one `Authorization` header, and never
stores, prints or logs it (an inline `api_key =` is rejected outright, and a
failing request reports endpoint + status only). Keep it in your shell profile or
a secret manager, not in the repo.

### Fallback rule

No `delvewright.toml`/`delvewright.local.toml`, no `[i18n]` section, or the named
env var unset ⇒ **fall back to in-agent translation** (the skill's default
behavior). A *malformed* `[i18n]` — unknown provider, missing `base_url`/`model`/
`api_key_env` — is an error, not a fallback: a typo must not silently downgrade
the pipeline.

### Pointing at DeepSeek or Kimi

Both speak the OpenAI chat-completions protocol, so only three lines change.
Confirm the current model ids in the provider's own console — they rotate.

```toml
# DeepSeek
base_url = "https://api.deepseek.com/v1"
model = "deepseek-chat"

# Moonshot / Kimi  (international endpoint: https://api.moonshot.ai/v1)
base_url = "https://api.moonshot.cn/v1"
model = "kimi-k2-0905-preview"
```

Steps, start to finish:

1. `cp delvewright.toml delvewright.local.toml` and uncomment the `[i18n]` block.
2. Set `base_url` + `model` from the table above; leave
   `api_key_env = "DELVEWRIGHT_I18N_API_KEY"`.
3. `export DELVEWRIGHT_I18N_API_KEY=<the provider's key>` in your shell.
4. Declare the language in the campaign's `world.json`: `"languages": ["zh-cn"]`.
5. `python3 tools/i18n-translate.py <campaign-dir> --lang zh-cn --dry-run` — prints
   the exact prompts and key list, sends nothing. Sanity-check the personas.
6. Drop `--dry-run` to translate for real; add `--reflect` for the three-step
   translate → critique → revise pass (below).

## The tool

```
python3 tools/i18n-translate.py <campaign-dir> --lang <code>
        [--dry-run] [--force] [--batch-size N] [--config PATH]
        [--delvec CMD] [--no-validate] [--reflect | --no-reflect]
```

Stdlib-only python3 (≥3.11). What it does:

1. Runs `delvec l10n-inventory <campaign-dir> --lang <code>` — the authoritative
   key inventory (exactly the key set `DW0180`/`DW0181` enforce), each row with its
   canonical English, the NPC whose dialogue tree it belongs to, and any existing
   translation.
2. Batches the untranslated rows into chat-completions requests carrying the
   speaking NPCs' persona (`speech_style` above all), a glossary of
   already-translated proper nouns for cross-batch consistency, and the rule that
   `.opt.<i>.label` keys are the *player's* reply. Low temperature; JSON-object
   replies; a reply that drops keys fails the run rather than writing a hole.
3. Writes `l10n/<code>.json` (keys sorted, exactly the inventory — orphans are
   impossible by construction), then runs `delvec validate` and reports coverage.
   Exits with validate's code.

**Idempotent**: a re-run translates only keys the sidecar lacks and rewrites the
file byte-identically when nothing is missing. `--force` retranslates everything.
`--delvec` (or `$DELVEC`) points at a built binary instead of `cargo run`.

## The reflection pass (`--reflect`)

A single-pass translation produces the first phrasing the model reaches for,
which is exactly where translationese lives. `--reflect` runs each batch as
**three steps** instead of one:

1. **Translate** — as above.
2. **Criticise** — a fresh call reads source and draft side by side and writes
   free-text criticism, one suggestion per problem, each naming its key. It is
   forbidden from writing a corrected translation: making the model *state the
   defect* is what stops step 3 from being a second roll of the dice.
3. **Revise** — the translator applies the critique, may reject it where it
   judges it wrong, and returns already-good lines **byte-identical**.

The critique axes:

| axis | what it catches |
|---|---|
| accuracy | additions, mistranslations, omissions, untranslated leftovers, mangled placeholders |
| fluency | target-language grammar and idiom, needless repetition, anything a native reader must re-read — **plus the target language's translationese checklist** |
| style / register | the speaking NPC's `speech_style`, hand-made-adventure register, `.opt.<n>.label` lines short and scannable, strings that still fit a chat line |
| terminology | glossary proper nouns verbatim, one English term rendered one way everywhere |

**Translationese is language-specific and lives in the prompt.** For `zh-*` the
tool carries a 翻译腔 checklist — 名词化, 弱动词 (进行/加以/作出), 的的不休,
over-marked 被, front-loaded relative clauses, reflexive 地/们/当……的时候,
redundant possessives — under one governing rule: exhaust the constructions
Chinese already has before importing one. 信达雅 is framed as a precedence
(信 → 达 → 雅, with 雅 meaning *the register the scene calls for*, not ornament).
A language with no checklist simply gets the general axes; a wrong checklist
would be worse than none.

**Anti-churn is explicit.** Reflection prompts rewrite unconditionally unless
told not to, and an unconditional rewrite degrades text that was already right —
so "no change" is stated as an expected verdict in step 2 and byte-identical
return is mandated in step 3.

Cost: three requests per batch instead of one. Off by default; `--reflect` turns
it on for a run, `[i18n] reflect = true` for a repo, `--no-reflect` overrides the
config back off. The `/new-delve` localization stage passes `--reflect`. Every
prompt in all three steps is printed by `--dry-run`.

Provenance: the three-step shape and the four critique axes follow
[`andrewyng/translation-agent`](https://github.com/andrewyng/translation-agent)
(MIT); the translationese checklist and the 信达雅 framing are our own, re-derived
rather than copied — see `docs/ACKNOWLEDGEMENTS.md`.

Art-styled `narrate` strings are glyph-validated against the `delve:art` font
(`DW0328`) in every declared language — if a translated art title trips it, that's
a real defect in the translation, not a check to relax.

## Comparison workflow

The point of the pluggable provider is to compare translators on the same
campaign:

1. Translate with the API (`--force` to redo an in-agent sidecar).
2. `git diff` the sidecar — the English side is fixed, so the diff *is* the
   comparison.
3. Owner reviews in-game where it matters: `delvec build --lang <code>` and play.
4. Hand-edit anything that reads wrong; re-running the tool preserves every line
   already present (only `--force` overwrites), so review edits survive.

Swapping provider = editing `base_url`/`model` and re-running with `--force`.
